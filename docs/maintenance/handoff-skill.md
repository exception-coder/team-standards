# 交接 Skill 共存与迁移

`cross-system-handoff` 从个人独立 Skill 纳入 Team Standards 5.1.0，正文保持可独立使用，无 Forge、全局脚本或私人路径依赖。它整理交接材料，发送消息、修改代码和发布仍按用户授权执行。

## 选择与真实加载

| 情况 | 执行约定 |
|---|---|
| 用户明确选择某一版 | 使用指定版本，保留项目必须遵守的规则 |
| 项目提供交接规则 | 项目版本优先，不再重复执行团队版 |
| 仅有团队套件 | 使用团队版 |
| 个人全局版与团队版都启用 | 两个候选可能同时出现；显式选择来源，不能保证模型隐式选择哪份 |
| 团队版已安装且个人版只是旧副本 | 经用户同意，保留个人文件并在宿主停用其入口 |
| 未安装团队套件 | 原个人版可独立运行 |

这里的项目版本不包括个人目录中的全局 Skill。正文里的优先约定是指导，不等于安装注册层自动去重；现有 openspec-auto 专项适配也不会处理这个 Skill。套件安装与升级不删除、覆盖或自动停用个人定制。

## Codex

官方说明：同名 Skill 不合并，两份可能同时显示；自动调用依据描述匹配。请从选择器选中 Team Standards 来源的交接 Skill，或明确指出插件内的 SKILL.md 路径。[发现与启停规则](https://learn.chatgpt.com/docs/build-skills)

个人旧副本停用采用 `~/.codex/config.toml` 的精确路径条目，路径取实际 `skills/list` 清单，不硬编码其他人的用户目录：

```toml
[[skills.config]]
path = "C:/actual-user/.codex/skills/cross-system-handoff/SKILL.md"
enabled = false
```

保留其他配置，不用 `name` 禁用整个同名集合。已有同路径条目应原位调整，后续匹配条目可能覆盖它。重载后核对个人路径已禁用、插件路径仍启用。恢复时将该路径设为 `enabled = true`，或删除自己新增的专用条目；卸载套件后需要个人版时同样处理。

## Claude Code 与其他宿主

Claude 团队版使用插件命名空间 `/team-standards:cross-system-handoff`；个人同名技能是另一个入口，不把命名空间等同自动去重。支持 `skillOverrides` 的版本可在 `/skills` 中停用个人入口，插件入口由 `/plugin` 管理；核对清单后再确认结果，见[官方发现与可见性规则](https://code.claude.com/docs/en/skills)。对其他宿主从技能清单确认实际来源，无法按路径停用时明确选中团队版，不自行重命名或删除个人文件。
