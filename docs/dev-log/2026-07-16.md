# 开发日志 · 2026-07-16

## 11:22 · 调整流程 · 项目知识图谱初始化与持续同步

**原因：** 原流程主要依赖 AI 重复扫描代码并维护 Markdown，缺少可再生的结构事实层、提交版本基线和失败状态保护，容易产生文档漂移，也无法清楚区分代码事实与业务语义。

**改动：**
- 将 Graphify 定位为优先的代码事实提供者，并为不可用场景保留确定性扫描降级路径
- 新增 `generated/` 投影和 `source_commit` 元数据约定，以 Git HEAD 判断知识新鲜度
- 将自动覆盖范围限制为生成事实和可证明的结构信息，领域语义继续要求人工确认
- 将持续更新改为事件驱动、影响范围刷新和每周完整重建兜底

**影响：**
- `init-project-docs` 首次建立生成事实层、项目说明层和领域知识层
- `project-docs-update` 根据 Git 基线刷新事实投影，并保护人工知识不被自动覆盖
- Graphify 安装、全局配置、计划任务和 CI 仍需用户明确授权，不由 Skill 隐式修改

## 14:05 · 修复规则 · 项目知识图谱与入职初始化路由冲突

**原因：** 用户表达“初始化当前项目文档和知识图谱”时，Yoooni 入职 Skill 因“初始化环境/拉项目文档”等宽泛触发词抢占路由，并在未确认入职意图时检查 SVN、准备创建凭据文件。

**改动：**
- 明确 `init-project-docs` 对“当前项目文档 + 知识图谱/Graphify”请求拥有优先路由
- 将 Yoooni 入职初始化限定为明确的新员工入职或 SVN 公司文档拉取意图
- 对泛化“初始化”要求先澄清，禁止在路由不明时读取或创建凭据

**影响：**
- 初始化代码知识图谱不再进入 SVN 入职流程
- Yoooni 入职流程仍可通过“新同事入职”或“SVN 拉取公司项目文档”明确触发
