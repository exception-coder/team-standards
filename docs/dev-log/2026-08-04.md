# 开发日志 · 2026-08-04

## 提交说明生成前移 · git-commit-standards

**原因：** 仅在 `git commit` 执行时阻断缺正文，依赖宿主启用并信任 Hook；而且阻断属于事后纠错，AI 仍可能先尝试只有标题的提交。提交正文承载需求背景和设计取舍，不能由只看到命令或 diff 的 Hook 准确补写。

**改动：**

- 将 `git-commit-standards` 调整为所有提交请求都触发，并要求在 commit 前基于会话上下文主动填写标题和中文正文。
- 新增统一消息生成器，由其校验输入、读取真实 Git 作者并写入消息文件，提交统一使用 `git commit -F`。
- 保留 PreToolUse Hook 作为独立兜底，继续阻断缺项和 AI 署名。

**影响：**

- Codex 与 Claude Code 的标准提交路径都会先形成完整说明，不再把 Hook 报错当作正常流程。
- 即使 Hook 因信任设置未运行，Skill 的主动生成流程仍能产出完整提交信息；Hook 可用时形成第二层防线。
