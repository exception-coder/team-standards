# 开发日志 · 2026-08-30

## 08:21 · 调整流程 · OpenSpec 自动生命周期

**原因：** `change-readiness` 过去允许已启用 OpenSpec 的项目在找不到相关 change 时静默降级到 legacy，Hook 也会被任意完整活动 change 放行，导致非极简行为或架构变更可能绕过 OpenSpec 规格生产。

**改动：**

- OpenSpec 项目的 M/L 变更强制自动匹配或创建 change，不再默认 legacy 降级。
- 复用官方 OpenSpec Skills 和 agent-compatible CLI，覆盖 artifacts、apply、update、verify、sync 与 archive 判定。
- Hook 只认可当前会话实际选择并读取的完整 change，无关 change 与 legacy 文档不再放行。
- 用户明确批准的单次兼容降级保留为受控例外。

**影响：**

- 开发者可以直接描述需求，不需要记忆 OpenSpec 命令。
- 已启用 OpenSpec 的项目在实现前必须产生或匹配相关规格变更，并在实现中持续维护。
- OpenSpec 工具故障会显式阻断，不再悄悄切换为另一套设计正文。

## 11:45 · 新增 Skill · delivery-verification

**原因：** AI Coding 的主要交付风险已从“无法生成代码”转为“生成后没有强制执行真实环境验证”；MCP 注册只提供能力发现，不能保证 Agent 在完成前调用，也不能阻止验证后继续修改却沿用旧 PASS。

**改动：**

- 新增完成前真实验证 Skill，优先调用 `forge_verify phase=all`，失败后最多进行 3 轮最小修复与复验。
- 新增 Stop Hook，通过 Git 工作区和当前 transcript 判断是否存在最后一次修改之后的 PASS 证据。
- 环境与业务场景继续由项目 `.forge/verify.yml` 管理，SQL/API 真实执行继续归 Forge Runtime。

**影响：**

- 有可执行改动的会话默认只有获得最新 PASS 后才能 Done。
- 纯文档改动不触发 Runtime；MCP 不可用时允许使用项目声明的 Forge CLI。
- 团队统一流程增加 `delivery-verification` 收尾门禁。
