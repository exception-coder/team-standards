# 开发日志 · 2026-08-13

## 22:42 · 新增 Skill · frontend-excellence

**原因：** 现有 `architecture-ddd-lite-fullstack` 能约束前端 Feature 分层与依赖方向，但不能保证视觉语言、设计系统、响应式、可访问性、交互状态和浏览器验收。继续扩写架构 Skill 会混合“代码放在哪里”和“产品体验达到什么标准”两类职责，并增加所有业务编码任务的上下文成本。

**改动：**

- 新增 `frontend-excellence`，负责生产级 Web 前端的设计与交付闭环。
- 将架构与状态、设计系统与美学、质量门禁拆为三份按需读取的参考资料。
- 在主编码链路中把它放在架构 Skill 之后、通用编码规范之前。
- 将 Figma 定义为可选增强输入，以截图、品牌资料和文字 brief 作为等价降级路径。

**影响：**

- 创建、重做或显著提升 React、Vue、Next.js 等 Web 前端时会自动触发新 Skill。
- 前端任务必须覆盖完整状态和关键视口，并以真实浏览器结果作为完成证据。
- 纯后端、原生移动端和无布局影响的文案小改不会触发。

## 22:50 · 修复规则 · git-commit-standards 提交正文闭环

**原因：** 2026-08-04 已决定所有提交都要主动生成正文，但主入口和 Skill description 仍保留“大改或用户显式提交才触发”的旧路由，导致小改与自动收尾偶发绕过；同时现有机械门禁只验证任意中文正文，无法保证说明代码做了什么、为什么做以及解决了什么。

**改动：**

- 将 `git-commit-standards` 的触发边界统一为任何提交前必走，改动大小只控制是否追加五步重审
- 将提交正文固定为 `【改动】`、`【原因】`、`【结果】` 三段式契约
- 让消息生成器和 Hook 复用同一校验器，并增加缺段回归测试

**影响：**

- 小改、自动收尾和未显式要求 commit 的提交也必须主动生成完整正文
- 后续提交历史稳定保留代码动作、决策依据与问题闭环
- Bash Hook 仍是机械兜底；不提供该 Hook 的宿主依靠 Skill 主动生成保证完整性
