# 2026-06-18 · warn 档 hook 命中事件本地登记（hook-event-logging）

## 背景

新规则推行用「先 warn 后 block」：默认 warn（命中只提示、放行），收集一段时间数据再决定要不要升 block。但 warn 是否有效、误报多不多、同事最常踩哪条，全凭感觉——缺数据。

## 决策

warn 档 hook 命中规则时，把一行事件 best-effort 追加到本地 `~/.kai-toolbox/hook-events.jsonl`，供后续统计「规则命中频率 / 升不升 block / 谁常踩」。

接入（team-standards 侧两道 warn hook）：
- `check-sql-ddl-readiness.js` → `rule: sql-ddl`
- `check-backend-kg-readiness.js` → `rule: backend-kg`

新增 `hooks/event-log.js`（`logHookEvent`）承载登记。事件含 `ts/user/host/plugin/hook/rule/mode/tool/file`，`mode` 同时记 warn / block——升 block 后仍继续登记，可对比升级前后命中量。

## 设计红线（为什么这么写）

1. **只写本地、绝不在 hook 里碰网络**：hook 是每次 Write/Edit/Bash 同步执行的热路径，SMB/网络 IO 一慢一断就拖慢每次编辑。本地 fs 追加是毫秒级。
2. **best-effort、绝不阻断**：登记全程 try/catch 吞异常——登记失败绝不能影响 hook 主流程（放行/拦截）的判定。登记是"附带能力"，不是 hook 的职责。
3. **不引第三方依赖**：只用 node 内置 `fs/os/path`。
4. **跨插件不共享模块**：team-standards 与 project-coding-profiles 独立安装，各放一份 `hooks/event-log.js`，但都写同一个 `~/.kai-toolbox/hook-events.jsonl`（project-coding-profiles 的 `check-file-encoding` / `check-frontend-controls` 同样接入）。

## 边界（与公司内网基础设施解耦）

team-standards / project-coding-profiles **只产生本地事件**，不感知 `\\IT01`、不做网络同步。下游"把本地 jsonl 同步到 `\\IT01\版本更新\vibecoding\hook-events-<user>-<host>.jsonl` + 周报统计"放在 `yoooni-daily-plugin`——保持通用规范插件与公司专有基础设施分离。

详见 `docs/design/hook-event-logging.md`。
