## 验证范围与完成阶段解耦

局部前端交互变更曾因最终交付要求全仓验证而执行无关后端测试；共享 delivery-verification 又将工具可用与强制 Forge all 阶段绑定，使项目按风险策略难以生效。

统一决策：先按影响和项目契约选择验证范围，再选择工具；M/L、归档、提交及会话切换不单独触发全仓。OpenSpec Scenario 可共享充分证据，提交可复用覆盖输入未变的证据；失败必须修复或报告，数据库与权限等必要运行证据保持要求。

静态情景审视：局部前端采用相关前端与浏览器验收；SQL 保留真实数据库证据；根构建/装配及影响不可界定触发全仓；无关文档或并行修改不作废无关证据；失败重验相关项并按新风险扩大。此为规则审视，不是实际 Agent 行为实验。

边界：未修改 Hook 或 Forge 引擎。现有交付 Hook 仍只接受 Forge all 阶段或声明 CLI 证据；受其约束的项目不能据新规则绕过门禁。后续若扩展 Hook，需要真实结构化执行证据、覆盖范围与新鲜度契约，不能仅把原生命令文字或任意 PASS 当作成功。

验证：三处版本同步 4.1.4、跨 Skill 引用检查和 Skill CI 审计通过；生成 AGENTS 与 CLAUDE 保持同步。无业务代码、Hook 执行逻辑或资源位置变化，本次不运行无关全量测试。工作区既有 onboard-workflow.md 修改及未跟踪 plugin.json 不属于本次提交。
