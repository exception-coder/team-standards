# 开发日志 · 2026-08-11

## 19:20 · 修复规则 · 架构约束可达性与机械门禁

**原因：** Skill 上下文瘦身把详细结构规则保留在 `rules/`，却遗漏了主入口读取路由；同时业务项目只有设计文档存在性检查，没有对跨工具依赖和跨 feature 内部引用执行机械阻断，导致原则声明无法阻止架构边界持续恶化。

**改动：**

- 架构 Skill 增加结构质量门禁的强制渐进读取条件，并明确后端工具模块、前端 feature 与 common 准入红线。
- 新增架构边界 Hook，客观依赖违规默认硬阻断，巨型文件增长采用软提醒。
- Skill audit 增加规则资源可达性检查，CI 阻断孤儿规则文档。
- 同步修复设计图表要求和知识图谱卡片模板两处既有不可达路由。
- 通用编码规范恢复 80 行函数阈值以及成功、失败、边界和 Bug 回归测试底线。

**影响：**

- 上下文精简必须同时满足“默认轻量”和“硬规则按场景可达”，不能再以文件仍存在代替有效路由。
- 业务项目新增跨模块依赖时会在写入阶段得到即时反馈；存量依赖不自动改写，需按模块逐步治理。

## 20:10 · 调整流程 · Plugin 与 MCP 版本递增门禁

**原因：** 三处 manifest 相等无法发现“三处一起忘升”的情况，MCP 也缺少源码变化与引擎版本之间的机械关联，安装缓存可能继续使用旧运行载荷。

**改动：**

- 三个 Plugin CI 增加运行载荷白名单与 Git 基线版本比较。
- MCP CI 增加引擎版本同步、相对基线递增及 catalog 新鲜度检查。
- 明确知识内容、测试和纯文档不触发引擎发版，避免无意义版本膨胀。

**影响：**

- 运行载荷变更漏升版本将直接阻断，纯知识更新仍可通过 `reload_knowledge` 快速生效。
