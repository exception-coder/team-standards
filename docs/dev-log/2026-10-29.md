## 架构可视化与 draw.io 模板（4.15.0）

同事建议将架构表达、绘图规范和视觉美化收敛为一个核心 Skill，附三套模板和轻量验收。仓库已有 `architecture-diagram-design` 承担相同意图，因此在原入口扩展，不新增竞争入口或破坏性改名；Skill 数量保持 22。

- 入口增加按受众选择 L1 汇报、L2 设计、L3 实施视图，以及图型、主线、形象表达和可编辑交付判断。视觉语言、draw.io 格式与验收按需加载。
- 三套原生 `.drawio` 覆盖四个案例：能力构成、资源维护与员工配置、当前执行、未来规划。SOP 明确可选，当前用户逐步推动，未来规划与程序校验有独立标识和拒绝分支；示例不充当项目实现事实。
- 用原生图元辅助识别，不绑定外链图标或新增绘图引擎。轻量验收分架构、表达、视觉和可编辑交付，不新增评分系统、治理 JSON 或 Hook。
- 实际渲染发现中文边标签逐字竖排、人物标签与资源库交叠、当前执行返回线穿过拒绝节点，分别修正标签样式、人物布局与返回路径，避免仅凭 XML 解析交付。
- 同步中英文 README、CLAUDE/AGENTS、流程、全景、变更记录、三处 manifest 与工作区总览。运行载荷升至 4.15.0；Forge 职责、执行协议和门禁均无变化，无需修改其架构合同。

验证：三套模板四页的 XML、ID、父子/边引用与几何检查通过；draw.io 中逐页打开、视觉审读，抽查原生节点改字并撤销、连接器起止端点，导出四份 SVG 和一份 PNG。四份 SVG 内嵌的节点、文字、样式、几何及同父节点顺序与最终源图一致。Skill 格式、跨引用、三处版本、生成入口、工作区总览、22 个 Skill 审计与 diff 空白检查通过；最终资源覆盖到隔离候选快照后，分发布局及 Codex 安装冒烟 4/4 通过，无跳过。插件未修改 Hook 行为，未重跑无关完整回归。

模板试画覆盖建议案例，不代表数字员工产品已实现，也不证明所有宿主的自动发现效果。已有其他未提交改动不纳入本次提交，已安装缓存和运行会话不会因源码更新自动升级。工作区根 README 的 4.15.0 总览已同步；其目录本身不是 Git 仓库，未计入插件提交。

## 第二轮：形象化表达、统一图标与原生编辑（4.15.1）

用户审阅首轮预览后指出图形仍偏传统流程图。问题不只是缺图标，还包括相似框体的视觉权重过于接近。因此重绘原三套模板，将视觉主次与图标编辑方法继续沉淀到原 Skill，不增加新入口、绘图引擎或审批。

- 能力图改成大面积核心主体与周围资源，区分方法和业务资源；SOP 仍独立标为可选指导，资源不串成执行链。
- 协作图以数字员工为主体，能力保留在员工边界内；公共资源采用集合，业务入口采用窗口形象，调用连接到可见窗口轮廓，协作扩展弱化并保留可选标记。
- 当前/未来执行分别以人物和模型为视觉主角，共用校验盾牌、工具箱与成果图形；保留当前用户推动、候选规划、程序授权边界、拒绝分支和规划中状态。
- 分发 13 项统一原生图标库，图元由矩形、椭圆与线段分组组成，无图片节点、外链依赖或锁定；采用标准 group 样式和分组选择设置。主节点数及可见容器层级不与图标内部图元数混算。
- 验收增加缩略图主次、同族图标、组合/单图元编辑及整体移动检查。实际副本中取消人员图标组合、单独移动头部并撤销恢复；员工整体移动时内部能力、边界和连接端点跟随；节点改字与连接器端点抽查后恢复。

验证：三份源图四页的 XML、ID、父子/边引用与几何通过；13 项图标均为原生未锁定分组。四页在 draw.io 实际打开审读，导出最终四份 SVG 和四份 PNG；八份预览内嵌的图元、文案、样式、几何及同父顺序与最终源图一致（按 XML 默认零坐标及字段序列化规则规范化比较）。最终候选的分发布局与隔离 Codex 安装冒烟 4/4 通过，无跳过；生成入口、引用、版本、Skill 格式及审计检查通过。不把此验证扩大为所有宿主的自动发现效果或真实业务实现验收。

三处 manifest 与受影响中英文说明、流程、入口及根总览同步至 4.15.1，Skill 仍为 22 个。没有 Forge 架构联动影响，也没有 Hook 行为变化；原有其他工作区改动保持原状。模板源文件与预览随插件发布，现有运行会话仍须更新插件才能加载新规则。
