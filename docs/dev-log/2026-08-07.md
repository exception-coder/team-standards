# 开发日志 · 2026-08-07

## 04:04 · 调整流程 · Skill 上下文渐进披露

**原因：** 两个团队插件的 Skill 数量和 description 体积持续增长，高频门禁又会连锁加载多个大正文，导致常驻上下文被挤占并增加误触发成本。

**改动：**

- 收窄 `team-standards` 与 `yoooni-daily-plugin` 的 Skill description，只保留触发边界
- 将四个高频大 Skill 重写为轻量入口，并把分类、目录、模板差异和技术栈细节下沉到一级 `references/`
- 保持 Skill 名称和第一阶段业务门禁不变，为后续合并入口 Skill 留出独立阶段

**影响：**

- Skill 列表中的常驻元数据明显减少
- 高频 Skill 触发后只加载核心工作流，详细规则按任务需要读取
- 插件使用者无需修改已有显式 Skill 调用名称

## 10:24 · 修改配置 · Hook 兼容、安全默认值与执行性能

**原因：** Codex 虽会用 `Write|Edit|MultiEdit` matcher 触发写入 Hook，但实际载荷仍是 `apply_patch`，现有脚本因只读取 `file_path/new_string` 而静默放行；同时提示词信号默认跨机上传、生产密码明文落盘，不符合最小权限和数据最小化原则。多个写入 Hook 串行启动 Node 进程也给每次编辑增加了明显固定延迟。

**改动：**

- 增加 Claude/Codex 写入事件适配器，统一处理多文件补丁
- 用单个 Node 进程内的 Worker 分发器并发执行写入规则
- 提示词信号改为脱敏、截断、最小字段和上传显式启用
- 生产日志密码改用 DPAPI，输出改为脱敏副本与短期保留

**影响：**

- Codex 写入不再绕过设计、注释、DDL、编码和前端规则
- 提示词及生产日志默认不再以明文跨边界流转
- 写入 Hook 的固定耗时显著下降，环境变量旁路与规则退出码保持兼容

## 17:01 · 调整流程 · 插件可靠性验证与发布闭环

**原因：** 单元测试和源码校验无法证明插件在真实 Codex 安装缓存中可被发现，也无法阻止两个独立仓库里的适配器和契约夹具逐渐漂移。安全与性能改造如果没有可重复门禁，也容易在后续迭代中退化。

**改动：**

- 增加隔离用户目录下的真实 Codex CLI 安装和 Hook 自动发现冒烟测试
- 用 Golden Fixtures、SHA-256 和工作区比较器约束跨仓写入契约
- 将生产日志安全、跨平台更新锁和 dispatcher 相对性能纳入独立测试
- 增加默认只读的 release dry-run，统一生成文件清单、压缩产物和 SHA-256

**影响：**

- 插件发布前可同时验证源码、安装缓存、运行入口和发布产物
- 两个插件继续独立安装，不引入共享运行时包；跨仓一致性由测试和发布门禁负责
- 耗时指标保持显式启用和字段最小化，不扩大现有数据采集边界
