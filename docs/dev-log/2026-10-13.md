## Codex Agent 试用审读

按新正文对专家的两个输入及负例执行本次 Agent 试用，非独立模型评测、非宿主自动触发验收：

- 输入：“我们需要让销售查询新品进度。”输出：“先确认进度来源、更新时间和销售的查询权限；复用已有接口，在进度页显示当前阶段、更新时间及异常原因。没有现成接口时，在现有服务内补受权限限制的查询。缺数据时明确提示。固定查询不能满足已确认的跨域需求时，再评估新的查询方式。”未默认建设 Agent/Graph；接口与页面仍是条件建议，未冒充已存在。
- 输入：“基于当前业务场景，通过构建统一能力底座，实现订单与生产信息全链路打通。”原句未说明是否已实现，按目标改写：“让用户从订单直接查到生产进度。”实现已确认时可写“从订单可以直接查到生产进度。”不通过文案推断状态。
- 负例：“停用在下一次鉴权请求生效。”保留为“下一次检查权限时，该账号会被拒绝”，不改成立即生效。原文没说明权限机制时不自行补部门规则；已采用消息重试且承诺最终完成时不为简单删掉持久化与幂等。

这些结果核对了当前范围与语义保护；跨任务自动发现及长期效果仍需宿主使用验证，不以格式或关键词通过宣称推理质量达标。
