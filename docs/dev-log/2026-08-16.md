# 开发日志 · 2026-08-16

## 03:30 · 修改 Skill · frontend-excellence 视觉判断与状态恢复

**原因：** 既有前端规范已经覆盖设计系统、完整状态和浏览器验收，但对“大圆角白卡、机械居中、巨大状态图标、装饰性阴影”等高频生成式 UI 默认模式只做了笼统提醒，缺少可执行的复核步骤；同时状态完整性尚未明确要求保留工作流上下文和提供恢复路径。

**改动：**

- 将“层级先于容器”和“视觉手段必须服务层级、可读性、交互或上下文”设为通用判断原则。
- 新增工作流状态参考，约束空、错、失效、无权限、校验失败的上下文与恢复路径。
- 新增真实渲染后的视觉复核清单，并接入浏览器完成门禁。
- 保持产品品牌方向在项目级规范中，不把 Apple、Linear、Vercel 或纺织材质固化为团队默认风格。

**影响：**

- 前端创建、重做和显著提升任务会主动检查无依据的 Card 化、机械居中和装饰性效果。
- 非正常状态存在可行下一步时不得形成 dead end。
- Card、圆角、阴影、渐变和玻璃材质并未被一刀切禁用，但必须能够说明其产品目的。
