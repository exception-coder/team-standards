# 开发日志 · 2026-08-16

## 03:30 · 修改 Skill · frontend-excellence 视觉判断与状态恢复

**原因：** 既有前端规范已经覆盖设计系统、完整状态和浏览器验收，但对“大圆角白卡、机械居中、巨大状态图标、装饰性阴影”等高频生成式 UI 默认模式只做了笼统提醒，缺少可执行的复核步骤；同时状态完整性尚未明确要求保留工作流上下文和提供恢复路径。

**改动：**

- 将“层级先于容器”和“视觉手段必须服务层级、可读性、交互或上下文”设为通用判断原则。
- 新增工作流状态参考，约束空、错、失效、无权限、校验失败的上下文与恢复路径。
- 新增真实渲染后的视觉复核清单，并接入浏览器完成门禁。
- 保持产品品牌方向在项目级规范中，不把 Apple、Linear、Vercel 或纺织材质固化为团队默认风格。

**影响：**

- 前端创建、重做和显著提升任务会主动检查无依据的 Card 化、机械居中和装饰性效果。
- 非正常状态存在可行下一步时不得形成 dead end。
- Card、圆角、阴影、渐变和玻璃材质并未被一刀切禁用，但必须能够说明其产品目的。

## 18:29 · 新增 Skill · Evidence-Driven Design Governance

**原因：** 单次前端实现规范无法跨临时目录和多个项目持续积累真实审美选择，也无法区分一次局部反馈、Profile 规律与 Global Core；需要把稳定工作流与持续变化的设计知识解耦。

**改动：**

- 新增 `design-system-bootstrap`、`design-system-guardian`、`design-observer`、`design-pattern-miner`、`design-reviewer` 五个 Skill。
- 新增用户级 Registry、Profile、Project Binding、Preference Evidence Schema、Resolver、Visual Eval Rubric 与 Approved / Rejected Reference Metadata 模板。
- 明确 Codex 个人 Skill 官方目录为 `$HOME/.agents/skills`，自定义设计数据固定在 `$HOME/.design-registry`。

**影响：**

- 有意义的 UI 工作可继承 Design Profile，并根据成熟度进入 Conservative 或 Controlled Exploration。
- 用户反馈先成为 scoped Evidence，经过重复验证才进入 Candidate、Established 或 Core。
- `frontend-excellence` 继续负责当前 Web 实现质量，新链路负责跨项目设计治理，两者在大型 UI 工作中叠加。
