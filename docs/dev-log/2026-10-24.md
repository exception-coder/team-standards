# 2026-10-24：以共同准则精简需求和方案判断

## 原问题与决策

专家建议增加 Requirement First，强调需求求真、最小充分和避免流程负担。现有 `architecture-reasoning` 已承担这些判断，另建同职责入口会产生重复。用户进一步明确，希望套件以“宪法”方式表达目标、准则和精炼反例，让 Agent 按事实判断过程。

检查 22 个 Skill 入口后，本次选取共同工程原则、悟道及旧方案审视作为有边界的精简切片。旧 `solution-review.md` 重复需求判断，保留固定六步流程、关键词强制触发和七项回显，与当前按影响执行的入口不一致。

## 本次调整

- 在既有 `engineering-principles.md` 维护工程宪法，明确共同目标、判断准则、实际底线及 Skill 如何承接；原路径保持兼容。
- 需求求真并入悟道，保留用户明确选择，按当前必要性判断复杂设计；使用现有 S/M/L，不增加第二套分级。
- 方案审视只保留生产改动取舍和少量反例，取消固定流程及回显模板。草稿、跨设备、敏感数据、通知、审批等条件对照放入已有 reference，按需读取。
- 同步入口、生成的 AGENTS、中英文 README、链路和套件总览；三处载荷版本为 4.14.1，Skill 数量仍为 22。

## 边界

未批量重写其他专业 Skill，未新增 Hook、审批、检查器或运行时设施。安全、权限、数据完整性、可靠性、既有选型和项目显式门禁继续适用。Forge 的职责、接口与执行协议未改变，因此不涉及关联 Forge 架构文档同步。

这是规则与分发元数据调整，不代表所有宿主已更新，也不证明 Agent 决策质量已提升。行为效果仍需在实际任务中用条件变化和真实结果观察。
