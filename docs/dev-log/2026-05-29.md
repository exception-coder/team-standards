## 注释红线单一来源化:`bugfix-coding-style` 红线表整体收口到 `coding-standards-common` §5.4 + §5.4.1

**原因:** 用户在 korepos `refund_confirm_service.dart` 上发现 AI 反复违规注释规则——私有方法 `_validateMethodsAmountSum` 上方写 12 行 dartdoc 讲"前端契约 / 早期版本曾要求 / 现已统一"的契约迁移史;`if (cancelBridgeServiceFeeAmount != null)` 上方堆 5 行行内 WHY 讲"另一分支怎么走 / 联台 scaleRatio / 不走本分支不受影响";section divider `// ===== [ADDED 2026-04-28] xxx =====` 风格分节标题带日期。用户原话:"代码内部不需要一堆废话注释 / 一堆分化注释主要说明函数能力和参数就行 / 每次改两个地方不友好吧"。

根因有两层:(1) AI 训练数据里学过的"代码注释包含变更历史 / 契约演变叙事"模式没有被 skill 显式列出字面反例,只有抽象规则。(2) `coding-standards-common` §5 和 `bugfix-coding-style` 红线表 99% 重叠却各写一份,新增反例要双地维护,容易漂移和遗漏。

**改动:**
- `coding-standards-common/SKILL.md` §5 顶部新增 **§5.0.0「写注释前 3 秒自检」执行配方**(4 问:可见性 / 行数 / 历史 / 场景),让 AI 动手前先过一遍
- §5.4 重写为「注释红线全语言、全场景单一来源」,显式声明 bug 修复 / 联调 / 删冗余 / 重构 / 新功能全适用,bugfix-coding-style 不再重复定义
- §5.4 列项追加:section divider 禁令 / 私有方法多段 dartdoc 禁令 / 行内 WHY 超 1 行禁令 / 变更日志列项扩字补"内部流水号引用 + `[REWRITTEN]` + `[MODIFIED]` + Issue 号 + Ticket 号" / TODO 列项扩字补"带个人或日期"
- **新增 §5.4.1 字面反例与原因对照表**(12 条),把抽象规则落到 AI 看得见的具体字符串字面(`// [BUGFIX 2026-04-30] xxx` / `// PR #1234` / `// TODO(zhangkai 2026-04): xxx` / `// ===== [ADDED 日期] xxx =====` / "私有方法 12 行 dartdoc" / "行内 5 行 WHY" 等)
- `bugfix-coding-style/SKILL.md` 红线表整体删除,替换为指向 common §5.4 + §5.4.1 的引用指针;frontmatter description 同步反映"不再独立定义注释红线"

## v1.29.0:新增第五道 hook `check-comment-density.js` 为 §5.4 注释红线做机械兜底

**原因:** 同一会话内,AI 在 korepos `pending_online_refund.dart` 表头给索引补注解时,又写了 4-6 行 `///` doc comment 把"注解只对 onCreate 生效 / 存量设备靠 migrateToVersion12/15 补 / 两者并存幂等"这种迁移共存史塞进源码。用户当场质问:"怎么写个代码又出现这么多注释 / 我的 plugin 没约束成功么"。排查结论:§5.4 注释红线此前**只在 skill 文档里**,纯靠模型自觉触发 `coding-standards-common`;`Write|Edit` 那道 PreToolUse hook 只管 DTO 注解 / 设计文档 / 后端知识图谱,**没有一条管注释**。会话漏触发 skill 时,红线形同虚设。

**改动:**
- 新增 `hooks/check-comment-density.js`(PreToolUse Write/Edit/MultiEdit,默认 warn):只扫本次**新增文本**(Edit.new_string / MultiEdit.edits / Write.content),去字符串字面量后判定注释片段,命中即 stderr 提示。抓客观无歧义项:变更标记 / 注释日期 / 工单·PR·Issue 号 / 带个人或日期 TODO / 带元信息分节线 / 版本流水措辞,外加连续注释块超阈值(默认 6)软提醒。
- `hooks/tests/check-comment-density.test.js` 23 例,含误报边界(`http://` / 字符串里 `[FIXED]` / UTF-8 / ISO-8601 不误判)。
- `hooks/hooks.json` Write|Edit 链注册第五道;`_comment` 改"五道"。
- `coding-standards-common` §5.4.1 末尾补「机械兜底」说明:hook 只抓客观项,prose 式实现史 / 私有方法契约史仍靠规则 + 评审,**不能因"hook 没报"放行**。
- `CLAUDE.md` 辅助资源表 + `README.md` hook 表 + `CHANGELOG.md` 新增 hook 条目;`AGENTS.md` 重生成;三处 manifest 1.28.11 → 1.29.0(MINOR,新基础设施)。

**决策原则沉淀:**
1. **规则只写进 skill 文档 = 靠模型自觉,会漏。** 客观无歧义的红线(标记 / 日期 / 工单号)应下沉成 hook 机械兜底,与 skill 形成"文档定规则 + hook 实施"双层防护——同 `check-design-doc` / `check-backend-kg-readiness` 模式。
2. **默认 warn 不 block。** 注释好坏含品味成分(4 行 doc comment 是公开 API 当前职责还是历史科普,机械判不准),硬 block 易误伤打断主流程。warn 模式先评估误报率,确有价值再考虑按项目升 block。
3. **hook 抓不全,要在规则源写清边界。** 本次用户被吐槽的具体注释(迁移共存 prose)hook 默认阈值其实抓不到——它不含标记/日期,是叙事。§5.4.1 明确"prose 式实现史仍靠 skill + 评审",避免给人"装了 hook 就不会再漏"的错觉。
