# 开发日志 · 2026-08-25

## 01:31 · 调整流程 · SQL 高风险查询性能门禁

**原因：** 实际排查中出现“Oracle 原生日期筛选较快，但计算结果筛选以 500 条为批次遍历全部候选，每个候选执行整套跨表查询后再由 Java 过滤分页”的方案。现有规范只要求核对 DDL、索引和过滤语义，无法稳定阻止 AI 把复杂度随候选量线性增长的查询直接写入代码。

**改动：**
- 将查询性能语义门禁并入 `backend-knowledge-graph-required`，覆盖无界聚合、应用层过滤分页、全候选批次遍历、循环数据访问和 N+1
- 要求落码前估算候选规模与最坏 SQL 次数，优先比较过滤下推、集合化、预计算和有界异步方案，并提供执行计划、调用次数或真实计时
- 高风险查询不得走极简设计档；Java SQL 规则同步增加分页后过滤、循环逐条查询和全量明细统计禁令
- 新增只告警不阻断的 `check-query-performance-risk.js`，用低成本启发式提示明显风险并保留独立关闭开关

**影响：**
- AI 遇到全量统计或派生筛选时必须先告警和给出优化建议，不能直接按现有慢模式落码
- 无可信数据库环境时允许继续设计，但必须标记“性能未验证”，不得宣称生产可用
- Hook 误报不会阻断编辑；是否允许保留扫描方案仍由 Skill 结合数据边界和运行证据判断

## 20:18 · 修复规则 · Oracle SQL 标识符兼容性

**原因：** Yoooni One 的 SLA 用纱查询将完整领域字段名 `non_purchase_preparation_recorded` 直接作为 SQL 列别名,超过目标 Oracle 兼容级别的 30 bytes 标识符上限,直到测试环境真实执行才暴露 `ORA-00972`。现有 SQL 规范覆盖字段真实性、注入和性能,但没有约束数据库方言的标识符长度。

**改动：**
- 在 `java-coding-standards` 的关系库 SQL 规范中增加目标数据库版本/兼容级别检查
- Oracle 未取得长标识符能力证据时统一采用 30 bytes 上限,要求 SQL 短别名与领域字段显式映射
- 将长度断言或目标 Oracle 解析测试设为新增、修改别名时的回归要求
- 在编码违规记录和反模式案例库登记本次真实故障

**影响：**
- AI 不能再以语义完整为由直接把长领域字段名复制成 Oracle SQL 标识符
- JDBC / MyBatis 映射保持接口和领域命名完整,数据库兼容性由短别名隔离
- 目标环境能力未经验证时采用保守上限,避免开发/Mock 测试通过而部署后 500
