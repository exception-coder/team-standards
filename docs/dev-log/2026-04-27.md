## 03:49 · 修改 Skill · 文档输出路径判定

**原因：** 用户指出当前 skill 默认把生成文档放在项目 `docs/` 目录，个人草稿或临时分析过多时容易影响团队成员，需要在创建输出目录时先构建合适的文档输出路径。

**改动：**
- 更新 `doc-index-required`，新增“文档输出路径判定”：团队共享文档写 `docs/` 并更新索引，个人/临时 AI 输出写 `.ai-docs/{agent}/{YYYY-MM-DD}/` 且不更新索引
- 增加 `.ai-docs/` 本地保护规则：优先写入 `.git/info/exclude`，不主动改团队 `.gitignore`
- 更新 `design-doc-required`，明确正式实施设计文档才进入 `docs/design/`，确认前草稿、扫描笔记、临时分析写 `.ai-docs/`
- 更新 `AGENTS.md`、`CLAUDE.md`、`README.md`、`docs/skill-flow.md` 与 v12 快照
- 更新 `.claude-plugin` 与 `.codex-plugin` 补丁版本

**影响：**
- AI 创建文档前必须回显输出路径判定，避免默认污染团队共享文档目录
- 个人文档默认成为本地忽略内容，不参与 `docs/INDEX.md` 维护
- 团队共享设计、Bug、API、知识图谱文档仍保留原有索引流程

## 04:00 · 新增 Skill · 方案审视与用户目录文档输出

**原因：** 用户进一步确认个人/临时文档不应写在项目目录内，即使本地忽略也会影响工作区观感；同时希望 AI 在用户提出想法并要求实施时，先判断有没有更好的建议和方案，而不是用户说什么就直接做什么。

**改动：**
- 新增 `skills/solution-review-required/SKILL.md`，要求在用户提出具体方案并要求实施时先分离真实目标与候选方案，识别风险、缺口和替代方案，再决定执行路径
- 更新 `doc-index-required`，将个人/临时 AI 输出默认路径从项目内 `.ai-docs/` 调整为用户 Documents 下的 `ai-docs/{project}/{agent}/{YYYY-MM-DD}/`
- 更新 `design-doc-required`，同步正式设计文档与确认前草稿的输出边界
- 更新 `AGENTS.md`、`CLAUDE.md`、`README.md` 与 `docs/skill-flow.md`，将新增 skill 接入主动触发链路，并创建 `docs/skill-flow-20260427-v13.md` 快照
- 更新 `.claude-plugin` 与 `.codex-plugin` minor 版本，便于团队成员检测到新增 skill

**影响：**
- 个人草稿、扫描记录、临时分析默认不再进入业务项目目录，减少对团队成员的干扰
- 今后用户给出具体实现想法时，AI 必须先审视目标、风险和更优方案，再进入设计文档或实施
- 正式团队文档仍写入 `docs/` 并保持索引维护流程

## 04:21 · 修复规则 · 文档默认输出统一到用户目录

**原因：** 用户希望不再区分个人文档和团队共享文档，避免 AI 判断输出归属带来额外复杂度；所有 AI 生成文档默认写入用户目录，最终终版文档由用户自行上传。同时用户询问为什么每次 push 仍可能需要授权。

**改动：**
- 更新 `doc-index-required`，将规则改为“用户目录默认”：AI 生成 Markdown 一律先写入用户 Documents 下的 `ai-docs/{project}/{agent}/{YYYY-MM-DD}/`
- 更新 `design-doc-required`，设计文档缺失时默认生成用户目录草稿，不自动写入 `docs/design/` 或更新索引；用户明确指定 `docs/...` 时才进入项目索引流程
- 更新 `git-commit-standards` 与 README，说明自动 push 是 skill 行为规则，但是否弹授权由 Codex / Claude / IDE 宿主审批策略控制
- 更新 `AGENTS.md`、`CLAUDE.md`、`README.md`、`docs/skill-flow.md`，并创建 `docs/skill-flow-20260427-v14.md` 快照
- 更新 `.claude-plugin` 与 `.codex-plugin` patch 版本

**影响：**
- AI 生成文档不再默认进入项目目录，也不再由 AI 默认判断团队共享/个人临时
- `docs/` 只在用户明确指定项目路径、上传终版或编辑已有文档时才被写入和索引
- push 授权无法由插件规则绕过，只能依赖宿主环境是否支持并保存命令授权
