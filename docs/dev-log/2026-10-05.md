## 真实 writer 未提交开发恢复（4.10.11）

- 原因：4.10.10 的新 change 首绑将 writer 已有代码视为初始脏文件；recover 又要求提交范围及 delivery，未完成任务无法恢复。未绑定的 snapshot 也无法取得审阅输入指纹。
- 决策：增加 recover-writer，消费 Forge v2 实时会话和 writer 归属，核对分支、HEAD、提交链、精确文件、并行归属、当前 preflight 审阅与暂存区。原点和原始指纹保留，恢复与 bind 两次核验；增加显式只读 preflight 计划快照。
- 边界：不生成交付证据、不关闭 task、不归档、不接管其他会话、不手改缓存。已完成切片的 recover/resume 不变。Forge WAITING_USER 必须通过有当前版本的宿主 resume 恢复，不能用重复进度上报冲掉 409。
- 联动：同步执行适配、自动设计维护、README 和关联 Forge 架构的恢复流程；恢复成功仅表示可继续开发，运行验收另行记录。

## 同会话多规格的兼容设计绑定修复（4.10.10）

- 原因：治理准备与绑定仅按项目和会话保存，自动推进切换 change 后仍使用上一规格范围，触发 SCOPE_GAP。
- 修复：通过 Forge execution v2 的 session_init 获取真实当前 change，按项目、真实会话及 change 选择兼容记录；同 change 的历史绑定保留，其他规格的证据不复制。设计准备、CLI 与 Hook 使用同一选择入口。
- 恢复：Agent 核对当前任务、文件及设计后补齐对应准备和绑定，重跑失败的设计检查；明确错配及归属异常，不伪造会话或扩大到整个仓库。自动推进交接说明同步在 Forge 架构正文。
- 验证：治理和设计准备 59 项通过、1 项真实 CLI 测试跳过；新增切换、历史兼容、身份错配及不可用 CLI 检查通过。当前业务会话新版运行恢复尚待验收，插件源码版本不代表宿主已加载。
