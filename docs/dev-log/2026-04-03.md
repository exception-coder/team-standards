# 开发日志 · 2026-04-03

## 修改 Skill · design-doc-required（新增接口请求示例要求）

**原因：** 设计文档缺少请求示例章节，开发/测试拿到文档后仍需猜测参数格式，无法直接发起调用。新增 5.5 节强制在新增接口时填写请求和响应示例。

**改动：**
- `skills/design-doc-required/template.md`：在第 5 节接口设计下新增 5.5 请求示例，含 HTTP 请求体、成功响应、失败响应三段示例
- `skills/design-doc-required/SKILL.md`：第三步最小章节要求补充"新增接口时 5.5 请求示例为必填"；第四步 coding 摘要生成规则补充"若存在 5.5 请求示例则原文提取"
- `skills/design-doc-required/coding-template.md`：接口契约章节新增"请求示例"小节，标注新增接口时必填

**影响：**
- 今后填写设计文档时，新增接口须补充请求示例
- AI 生成 coding 摘要时自动提取请求示例到 coding.md，编码阶段可直接引用

## 修改 Skill · design-doc-required（新增接口 DTO 独立约束）

**原因：** 新增接口若复用已有接口的 Request/Response DTO，会导致两个接口耦合；任意一方字段变更都可能破坏另一方调用方。需在设计文档阶段强制约束。

**改动：**
- `skills/design-doc-required/SKILL.md`：第三步最小章节要求补充"新增接口时，必须定义独立的 Request/Response DTO，禁止复用已有接口 DTO"；红色警告表新增对应条目

**影响：**
- 今后新增接口设计文档时，必须显式声明独立 DTO，不可复用旧接口 DTO

## 修改 Skill · git-commit-standards（参考 superpowers 设计增强可靠性）

**原因：** AI 在执行提交时跳过了 git config 读取、未等用户确认直接提交、并擅自添加了 Co-Authored-By 署名。根因是 skill 缺乏强制性语气、没有 Red Flags 拦截合理化念头、步骤也没有与 TodoWrite checklist 联动。

**改动：**
- `skills/git-commit-standards/SKILL.md`：
  - 新增 `<EXTREMELY-IMPORTANT>` 块，声明 Rigid 属性，禁止跳步
  - 新增"五步执行清单"，要求用 TodoWrite 逐条跟踪，步骤间串行
  - 新增 **Red Flags** 表，覆盖 7 种典型合理化跳过念头
  - 第四步"确认"改为刚性要求，明确写出"禁止未收到确认就执行 commit"
  - 第五步在禁止项中显式列举 `Co-Authored-By: Claude`、`Generated by`、emoji 署名
  - 删除原"禁止行为"表（内容已整合进 Red Flags 和各步骤说明中）

**影响：**
- 今后执行提交必须走完五步，每步都有明确的暂停/继续条件
- AI 无法以"简单提交"为由跳过 diff 分析和用户确认
