# 2026-09-14

## 业务图表看板纳入前端设计层（4.1.0）

原因：管理层经常关注指标与图表，原有前端实现和视觉系统没有独立承接业务状态到指标洞察的设计任务。

决策：新增 business-visualization-advisor，并由前端入口条件路由；语义事实、信息设计、视觉系统、实现验收职责分离。专家建议与个人技能迁入团队载荷，管理看板补充目标、差距、原因与行动层次，公式、历史和归因仍需证据。设计依据见 ../design/frontend-excellence/frontend-excellence-current.md 第 10 节。

影响：16 个团队 Skill，三处元数据同步 4.1.0；无新增 Hook、运行时引擎或库依赖。个人副本在团队版本安装验证后退出自动发现，避免重复维护。

验证：Skill/插件校验、交叉引用、16 个 Skill 审计、三处 4.1.0 版本及安装烟测 2/2 通过。逐项审视普通页面不触发、业务看板正常路由、无历史不生成趋势、无权限不报零和无目标不生成达成率；这是规则场景审视，不宣称已运行真实业务页面。

## 看板优化的选图决策门槛（4.1.1）

用户反馈：读取规则后仍可能过早收窄为布局修改，且登录阻断导致缺少视觉复核。加强显式看板优化的候选清单、逐项决策、未改变图表的编码前说明和交付分类；保留无图合理选择与纯样式边界，不新增审批。替代预览必须标明数据与验收限制。同步源码与本机安装，以发布版本为唯一活动来源。
