# 开发日志 · 2026-08-09

## 04:41 · 新增 Skill · domain-spec-mining-required

**原因：** 既有设计文档、后端知识图谱和反向索引能约束“怎么分析”，但不能从遗留系统分散证据中重建对象状态、关联解除、不变量和下一动作，导致 AI 仍可能在当前接口成功后提前结束。

**改动：**

- 新增对象中心、证据驱动的规格挖掘门禁。
- 明确 Graphify 只负责静态事实，确定性挖掘由 project-domain-knowledge 单一实现承担。
- 建立 observed、inferred、candidate、confirmed 四级证据与人工晋升边界。
- 评审绑定候选证据版本；新证据出现后旧决定保留为历史但自动过期。
- 把对象终态、关联解除、失败/幂等、数据库断言和下一业务动作纳入编码前合同。

**影响：**

- 订单、库存、审核、取消、退货、调拨和占用类状态需求在规格缺失或冲突时，需先执行 `domain-spec-mining-required`。
- 核心调用顺序在后端事实图谱与反向影响索引之间增加规格挖掘步骤。
- Yoooni ERP 自动开发流水线将消费候选规格，但不得自动把候选升级为稳定业务真理。
