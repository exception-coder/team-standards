# Bug 调查与修复

## 诊断

确认触发输入、操作和环境，区分实际现象与预期；预期应来自用户、已接受契约或权威实现。用最小复现、失败测试、日志、数据和调用路径区分事实与假设，优先执行能排除不同原因的检查，不堆补丁代替诊断。

不能复现或证据不足时说明缺口、未排除原因和下一步，不能把猜测写成已确定根因。使用项目可用的证据源；没有外部知识库或图谱时直接定向查源码和运行证据，不等待未接入工具。

## 修复

- 只问原因且没有修复授权时交付诊断；用户已要求修复时，在证据足够后继续实施，不因阶段变化重复询问。
- 先核对受影响调用方、状态、存储与失败路径，再作满足当前目标的最小修改。发现阻塞某个操作的业务歧义时只暂停依赖它的部分。
- 修复采用 [编码](../foundation-coding/SKILL.md) 与 [注释](../foundation-comments/SKILL.md) 规范，不夹带无关重构或历史治理。
- 优先用已有用例重现原问题并验证修复，必要时补充独立失败或边界风险。按 [验证规范](../foundation-verification/SKILL.md) 执行回归，不能把构建通过当作原 Bug 已复现并解决。

## 记录与交付

简单局部问题由会话、测试和提交说明承载，无需新建 Bug 目录、报告和图。跨模块、反复发生、难复现或涉及金额、权限、数据丢失的问题保留可接手的证据与未决条件；优先补充已有问题记录，用户要求或没有合适载体时才新增文档。

说明证据支持的原因、修改、实际回归结果及剩余限制。未修复或未验证时如实报告，不能以填齐模板宣称完成。必要文档和提交按项目约定处理，外部 Issue 的写入另需已有授权。
