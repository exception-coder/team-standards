# 基础编码规范

实施前读取项目约定和相关代码，确认行为、调用方及现有扩展点。已有依据充分时直接实施；局部修改不以历史文档缺失为由补齐整个模块。

## 结构与实现

- 名称表达具体业务对象和动作，沿用项目已确认的风格；不以 `Util`、`Helper` 或 `Manager` 收纳互不相关职责。
- 函数围绕一个清晰职责组织；当步骤难以理解、规则独立变化或难以验证时提取函数或服务。行数、参数数和嵌套深度用于发现问题，不当作必须拆分的配额。
- 沿用已有模块和分层边界，保持依赖单向。业务规则不依赖 UI、传输 DTO 或具体存储适配器；不在页面或 Controller 堆放独立业务规则。
- 新文件先找已有落点；同层有多个稳定职责簇时按语义分包，职责内聚时保持扁平。不为形式完整增加空层、空接口或通用扩展框架。
- 新增能力先查已有实现；区分重复知识与相似但独立变化的逻辑。稳定约定维护一处，避免在配置、代码和文档多处重复映射。
- 魔法值改用有语义的常量、枚举或配置。新增全局注册名、路由、事件或配置键前查重。
- 外部 API 和不熟悉的库先核对项目版本与官方契约，不凭记忆编造方法、字段或参数。

## 正确性与边界

- 异常不可静默；在责任边界记录必要操作上下文，返回或传播可识别的失败。预期业务失败与程序缺陷分别处理，不用兜底成功掩盖失败。
- 校验外部输入和权限；数据库操作参数化，不拼接不可信 SQL，不将凭据或敏感载荷写入源码、日志和报错。
- 文件、连接、响应体、锁和后台任务有明确生命周期。涉及事务、重试或并发时核对真实原子性、幂等和退出方式，不仅靠表面代码结构判断安全。
- 默认聚焦当前任务；不顺手升级依赖、重构全仓或转换编码。保留存量文件的字符编码与项目换行约定，非 UTF-8 文件按其原编码安全编辑。

## 注释与交付

新增或修改源码时同时适用 [代码注释规范](../foundation-comments/SKILL.md)，包括新增代码尚未写注释的情况。检查必要注释是否缺失，不能仅检查已有注释是否简短。

对核心成功、失败和边界风险选择 [适用验证](../foundation-verification/SKILL.md)；优先补充已有套件，不为每一条规范新增测试。同步受影响说明，核对本次 diff 未夹带无关修改。
