# 基础平台项目模板交接包

版本：1.1.0。将本目录的 `template/` 内容随项目模板生成并纳入项目 Git；无需预先安装 team-standards，也不依赖外部 MCP、脚本或个人目录。

## 交付内容

| 文件 | 用途 |
|---|---|
| [template/AGENTS.md](template/AGENTS.md) | 项目必读约定与六类任务的本地 Skill 路由 |
| [template/CLAUDE.md](template/CLAUDE.md) | 引导其他宿主读取同一份项目约定，不维护第二份规则 |
| [编码规范](template/.agents/skills/foundation-coding/SKILL.md) | 命名、职责、依赖、复用、错误、输入、资源与编码保护 |
| [代码注释](template/.agents/skills/foundation-comments/SKILL.md) | 新增业务代码的职责说明、公共契约、字段含义和非显然原因 |
| [Bug 调查与修复](template/.agents/skills/foundation-bugfix/SKILL.md) | 证据、因果、最小修复与回归 |
| [交付验证](template/.agents/skills/foundation-verification/SKILL.md) | 按风险选择检查并报告真实结果 |
| [Git 提交](template/.agents/skills/foundation-git/SKILL.md) | 原子提交、中文说明、真实作者及提交和推送边界 |
| [文档同步](template/.agents/skills/foundation-docs/SKILL.md) | 同次更新受影响说明、唯一正文与格式检查 |
| [manifest.json](manifest.json) | 模板版本、文件入口和原套件来源映射 |

六个 Skill 使用 `foundation-` 名称，与原套件的调用名区分。新增或修改源码同时适用编码与注释规范，不能等到用户要求补注释时才触发。

## 基础平台接入

1. 将 `template/` 的内容合并到平台的项目模板源，保持隐藏目录 `.agents/` 完整。发布包应包含根入口、六个基础 Skill 和两个宿主路径的 openspec-auto，不能只复制可见文件。
2. 新项目直接生成这些文件；已有项目先比较并合并原有 `AGENTS.md`、`CLAUDE.md` 与本地 Skill，不覆盖项目独有规则、不删除其他能力。
3. 在项目约定里补充真实的启动、构建、测试命令和技术栈规则。使用实际已有配置，不生成看起来可用的占位命令，也不因采用基础包安装测试依赖或初始化治理工具。
4. 项目提交后，这份模板快照就是该项目采用的基础版本。后续版本由平台明确升级并审阅差异；不要运行时从个人插件目录取正文或自动追随最新版。
5. 在目标宿主的新会话中核对入口和 Skill 是否可见，再运行下方验收场景。Codex 从仓库 `.agents/skills/` 发现本地 Skill；同名 Skill 不会自动合并，详见 [官方技能说明](https://learn.chatgpt.com/docs/build-skills#where-codex-loads-local-skills)。其他宿主通过其项目入口读取这些文件，发现路径和接线需分别验收。

`AGENTS.md` 保留无插件时也能理解的最低要求，详细做法由本地 Skill 承载。Codex 的项目入口读取方式见 [官方项目约定说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

## 与同事现有套件共存

| 环境 | 项目采用的基础规则 | 平台应核对的事项 |
|---|---|---|
| 没有安装套件 | 项目入口与本地六个 Skill | 根入口和隐藏目录已随模板生成 |
| 只安装 team-standards | 项目明确选择的本地基础版本；外部套件提供专项能力 | 不改为读取个人安装目录中的同类基础规则 |
| 已有其他基础插件 | 同上 | 本地与外部同类 Skill 的任务路由是否明确 |
| 多份套件或插件并存 | 同上 | 版本、启用状态和重复 Hook；不能只根据缓存目录存在判断已生效 |

项目入口明确六类任务优先使用本地文件，这是一项 Agent 作业约定，不是宿主自动屏蔽插件的机制。安装外部套件后，平台仍应核对它注册的 Hook；选择本地 Skill 不会关闭外部 Hook。重复或互相矛盾的检查应在宿主实际支持的配置中去重；不能单独停用时使用兼容的套件版本或调整启用组合，不为了通过编辑临时绕过项目要求。

本包没有注册 Hook、修改全局配置或卸载同事的插件。原套件的 Skill 保留以兼容旧项目；本次交接不要求所有同事同步升级。未验证某个宿主的发现或去重行为时，明确记录待接入，不能宣称全员已经生效。

## 注释要求与原规则的区别

原套件的注释细则主要按信息需要补充说明。此模板明确增加新项目要求：新增业务类、业务模块和对外复用组件应说明职责及边界；新增或改变公共 API 时应说明调用契约。改码时同时检查必要注释是否缺失，以及已有注释是否已失效。

采用语言原生文档注释，不给简单访问器、明显的私有步骤或生成代码机械补注释。不限制固定行数，也不因出现日期、工单号就删除仍有效的法律、协议或兼容说明。完整规则只维护在 [代码注释 Skill](template/.agents/skills/foundation-comments/SKILL.md)。

注释是否解释了真实业务含义需要语义审阅。平台若要求提交时强制检查公共 API 文档，应按实际语言接入已有 lint、构建或 CI；模板文件存在和静态结构检查不能证明代码注释已合格。

## 平台接入验收

以下是接收方的行为验收场景，不代表本包已在同事电脑上执行过：

| 场景 | 应观察到的行为 |
|---|---|
| 无插件环境新建业务类和公共方法 | Agent 读取项目约定与本地规范，补职责、调用契约；未因缺少插件停止作业 |
| 新增状态、金额或时间字段 | 注释说明状态语义、单位或时区等名称无法完整表达的条件 |
| 修改公共方法的失败语义 | 同步对应文档注释与受影响说明，不保留旧承诺 |
| 修改明显的私有访问器或生成代码 | 不添加逐行翻译；生成代码通过生成源或配置维护 |
| 排查一个局部 Bug | 先区分证据与假设，修复后执行适用回归，不强制生成独立报告 |
| 提交前存在同事的未提交或暂存内容 | 只提交本次可分离逻辑单元，不重置或夹带他人改动 |
| 项目有昂贵集成测试，当前只改局部行为 | 选择覆盖实际风险的检查，不能把未运行或跳过写成通过 |
| 同时启用旧套件和本地模板 | 六类基础任务采用本地版本；检查并记录外部 Hook 是否重复 |
| 下载并解压交接包 | `template/.agents/skills/` 六个入口均存在，所有本地链接在包内可解析 |

## 维护归属与交接边界

基础平台维护模板发布、版本升级、宿主适配和项目接入验证；项目维护实际命令、业务边界和明确例外。此目录是 1.1.0 模板源，`manifest.json` 标明提取来源；不与个人插件目录建立运行时依赖。

本次从通用编码、注释、Bug、验证、Git 和 Markdown 能力裁剪，并吸收单向依赖、最小充分复杂度和清晰表达原则。完整 DDD 目录、Java/Go/LLM 专项、UI、数据库证据、业务建模与规格治理按项目需求另外接入，不作为模板启动前提。推送白名单、套件升版脚本、遥测和治理登记均未带入项目模板。

交接后先在一个全新项目完成上述行为验收，再扩入其他模板。不要通过删除原套件能力来代替验证，也不要把这一份独立模板宣称为已经完成整个套件的依赖拆分。

## OpenSpec 智能分级（1.1.0）

新增 [openspec-auto](template/.agents/skills/openspec-auto/SKILL.md)，另有 [Claude 原生发现副本](template/.claude/skills/openspec-auto/SKILL.md)。两者从套件同一源复制，CI 比较正文与随附脚本，禁止独立维护两套标准。其余六类基础规范继续有效。

Skill 本身不要求 Node、Team Standards 或 Forge；可选风险下限核对脚本需要 Node。L3 调用项目真实安装的 OpenSpec，模板不伪造 `openspec/config.yaml` 或代替平台安装工作流。Plan S 发布模板时保留原有 OpenSpec 配置与质量门禁。

共存安装使用 [项目优先适配](../../docs/maintenance/openspec-auto.md)。普通全局安装不会自动感知所有项目；接收方须把注册选择接入自己的启动器，或使用该适配返回的宿主参数。不要把 AGENTS.md 约定当成物理去重。升级只在明确操作时审阅差异，禁止运行时覆盖项目副本。
