# OpenSpec 自动分级

一份标准、两种分发方式、项目执行优先。本 Skill 可直接复制到项目中，不依赖 Team Standards、Forge、个人安装目录或全局脚本。

## 先确定唯一入口

先读项目约定和本地 Skill。项目有同类能力时，以项目内置版本为准，停止执行全局版本的分类步骤；不同宿主路径中的同一份副本只执行一次。不重复分类、初始化 OpenSpec、创建 change 或运行工作流。不自动更新或覆盖项目文件。

项目声明的更严格要求继续适用；用户指令与更高优先级约束仍须遵守。这里的 L1/L2/L3 表示规格深度，与风险等级、架构图层次及 Forge 阶段无关。

## AI 判断，不让用户选等级

阅读当前需求、相关实现、已有规则和测试，判断影响范围、业务规则、权限与数据风险、兼容性及不确定性。不要用文件数、行数或关键词代替语义判断。只有无法从上下文确认的业务选择才询问用户。

| 等级 | 判断依据 | 执行 |
|---|---|---|
| L1 | 局部、明确、低风险；如文案、样式、恢复已约定行为的简单 Bug | 直接实施、适用验证；不新增计划、规格或报告 |
| L2 | 有限模块内的功能或调整，业务规则明确，兼容且无高风险影响 | 简述目标、步骤、验证；复用会话或已有任务计划，确有交接需要才保存必要计划；实施、验证 |
| L3 | 架构边界、跨系统复杂流程、重要数据模型，或下述高风险条件 | 使用项目已安装的完整 OpenSpec 工作流，复用匹配 change、规格、设计和验收 |

**强制 L3：**权限/身份/租户隔离边界、数据安全或完整性、敏感数据处理、不可逆迁移或删除、破坏性 API/协议/兼容性变更。修复只有一行也不能豁免。普通页面展示已有权限不等于改变权限边界，需检查实际行为。

影响未知时先定向调查，不能把未知当低风险，也不为未知自动生成整套文档。存在可信的高风险迹象时先按 L3 处理相关工作，再补齐证据。

## 执行与升级

1. 简短说明采用等级、具体原因和验证范围；已有当前任务判断时沿用，不在每次工具调用或续接时重分级。
2. L1/L2 维护受影响的现有说明和契约，不为了等级生成空规格。项目明确要求该类变更走 OpenSpec 时升级到 L3。
3. L3 先检查项目 OpenSpec 配置、安装版本、现有工作流 Skill 和活动 change；按该项目的准备、实施、验证流程推进。不得另装全局版本、重复初始化或编造命令。未安装时说明所缺能力，继续独立可执行的调查与计划；需要安装时按项目既有授权处理。
4. 发现范围扩大、跨模块耦合、业务规则变化或兼容风险时立即重新评估并升级；把已完成工作纳入同一任务/change，保留原 session、writer、验证证据和任务状态。不能为降流程成本拆小任务或自动降级。
5. 复用项目已有 SQL Gate、API Gate、测试、构建及明确采用的 Forge/CI 要求。等级决定规格深度，**实际变更风险决定验证范围**；L1 也可能需要关键回归，L3 不代表每次全仓重测。缺少 Forge 不影响独立运行。
6. 收尾给出最终等级、判断或升级原因、实际验证结果及未验证项。测试未跑、跳过、失败不能写 PASS；不自动勾选未完成任务、归档或宣称上线。

可选的 [分级下限核对器](scripts/risk-floor.mjs) 接受 Agent 已核实的风险事实，防止高风险或已升级任务被降级；它不理解需求、不代替 AI 判断，也不是项目运行依赖或提交门禁。

## 示例

- 修改按钮间距且不改行为：L1，检查页面显示与交互，通常无新增文档。
- 已明确规则的模块内兼容筛选功能：L2，轻量计划并验证相关行为。
- 筛选实际改变租户数据可见范围：升级 L3，复用项目 OpenSpec，并核验越权与兼容场景。
- 无插件的 Plan S 项目：仍按本文件分级、运行项目工作流与门禁。
