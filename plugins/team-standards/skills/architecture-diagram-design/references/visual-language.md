# 视觉语言与模板选择

绘图时按需要采用，项目已有规范和用户明确选择优先。模板中的数字员工仅用于演示表达方法。

## 三套模板

| 模板 | 表达方式 | 调整重点 |
|---|---|---|
| [能力构成](../assets/templates/01-capability.drawio) | L1，大面积实色能力主体居中；方法与业务资源分列两侧，统一线性图标 | 箭头由能力指向按需引用的资源；SOP 独立置底、可选指导，不是必经执行步骤 |
| [系统协作](../assets/templates/02-system-collaboration.drawio) | L2，资源集合、机器人主体与内部能力、办事窗口各用有语义的形象 | 仅员工范围显式画边界；维护、引用、调用方向明确；协作扩展弱化并标记可选 |
| [执行对比](../assets/templates/03-execution-comparison.drawio) | L3，人物/模型为主角；校验盾牌、工具箱、成果文档共用同一阅读路径 | 当前突出用户推动；未来突出候选规划且标注规划中；拒绝分支与正常主线分开，不把模型画成执行授权者 |

## 配色与形态

| 语义 | 默认强调色 | 用法 |
|---|---|---|
| 核心主体 | `#2563EB` | 主要能力或系统；小面积实色主体配白字 |
| 方法 / 智能能力 | `#7C3AED` | 方法资源、模型规划；标签继续区分语义 |
| 业务资源 / 成果 | `#0D9488` | 知识、工具、入口或成果；标签区分对象，不凭绿色宣称已实现 |
| 控制 | `#B45309` | 权限、程序校验与风险关卡 |
| 正文 / 辅助 | `#14213D` / `#66758B` | 浅色背景上的文字 |
| 页面 / 分区 | `#FFFFFF` / `#F8FAFC` | 留白与分组 |

优先区分三层：核心主体用较大面积与实色或清晰边界；支撑对象用浅底、统一图标和深色短标签；说明与可选扩展用低视觉权重。缩成缩略图时应仍看得出主角和阅读路径；不要求所有图都出现实色大圆或照搬模板比例。浅底常用 `#EFF6FF`、`#F5F3FF`、`#ECFDF5`、`#FFFBEB`。

强调色适合图形、边框和核心主体；普通文字优先深色。颜色始终配合形状、位置或标签；虚线若表示可选，应有“可选”文字，不同时表示另一种状态而不解释。

## 统一图标与语义

draw.io 原生编辑优先使用 [13 项原生图标库](../assets/native-icon-library.xml)。同一套图标采用 64×64 基准画框、约 2.6 单位线宽、圆角及不填色的线性主体；放大时同步缩放笔画。形状与图标可随对象缩放，保持比例、留白和家族一致，不混搭随机 Emoji 或不同拟物风格。

| 对象 | 图标隐喻 | 仍须保留的文字 |
|---|---|---|
| 人员 / 数字员工 | 人物 / 机器人 | 角色与职责 |
| 工作能力 / Skill | 组合模块 | 能力名称与必要限定 |
| Prompt / SOP | 对话框 / 清单板 | 指引或可选流程语义 |
| 知识 / Tool | 书本 / 工具箱 | 业务事实或系统操作能力 |
| 模型 / 校验 | 芯片 / 盾牌勾选 | 候选规划、程序权限与约束；盾牌不等于校验一定通过 |
| 入口 / 成果 | 办事窗口 / 勾选文档 | 使用方式或交付内容 |
| 协作 / 拒绝 | 多人 / 禁止标志 | 可选扩展或拒绝原因 |

图标是识别辅助手段，不是架构组件清单；不能为了凑图标虚构流程或状态。用户明确要求原生可编辑时，不把 SVG 图标当作可拆分图元。项目已有图标系统仍可优先，但须满足本次编辑深度要求。

## 布局与文字

先选主线，再选横向、分层、辐射、卡片或左右对比布局。相同职责同尺寸，不同职责按信息权重区分；避免所有节点等大、等深、等边框。对齐同级节点，给文字和连线留空间；不要用网状箭头代替分组。层次本身可说明包含，但不能抹掉真实安全边界。

模板以 1600×900 为起点，标题约 40、核心主体约 32–36、节点约 24–28、辅助约 18–20；这是可调整的起点，不是所有图的强制阈值。按最终投影、正文或手机尺寸检查；太密时删去可下沉说明或拆图，不无限缩小字号。字体使用系统可用的中文字体并设置后备，三层文字足够。通常两层的限制针对可见业务容器；图标内部的技术分组不算架构层级，也不计入主节点数量。

节点用短名称和必要限定，长解释归正文。避免装饰阴影、密集浅矩形、无意义图标和大段边注。检查箭头标签是否压线，不能为了绕线发明中间组件。
