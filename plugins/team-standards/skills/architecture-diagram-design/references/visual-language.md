# 视觉语言与模板选择

绘图时按需要采用，项目已有规范和用户明确选择优先。模板中的数字员工仅用于演示表达方法。

## 三套模板

| 模板 | 表达方式 | 调整重点 |
|---|---|---|
| [能力构成](../assets/templates/01-capability.drawio) | L1，工作能力居中，方法、知识与工具围绕主体 | SOP 只是可选指导，不串成强制执行链；资源不是流水线步骤 |
| [系统协作](../assets/templates/02-system-collaboration.drawio) | L2，公共资源、员工配置、业务入口分区 | 线上的“维护、引用、配置、调用”含义不同；协作扩展明确标记可选 |
| [执行对比](../assets/templates/03-execution-comparison.drawio) | L3，两页保持相同阅读方向，分别呈现当前与规划 | 当前由用户逐步推动；未来模型仅提出分工，程序校验通过才执行，拒绝不进入执行 |

预览与源图对应：[能力构成](../assets/templates/01-capability.svg)、[系统协作](../assets/templates/02-system-collaboration.svg)、[当前执行](../assets/templates/03-current-execution.svg)、[未来规划](../assets/templates/03-future-planning.svg)。SVG 由 draw.io 从对应源图导出，编辑后应重新导出。

复制 `.drawio` 到项目指定位置后替换事实，不直接覆盖随插件分发的模板。只采用需要的页，不为凑模板制造组件。

## 配色与形态

| 语义 | 默认强调色 | 用法 |
|---|---|---|
| 核心主体 | `#3B82F6` | 主要能力或系统 |
| 智能能力 | `#8B5CF6` | 模型规划、智能决策 |
| 成果 | `#10B981` | 已产生的交付物；不表示规划已完成 |
| 控制 | `#F59E0B` | 权限、程序校验与风险关卡 |
| 正文 / 辅助 | `#1F2937` / `#64748B` | 浅色背景上的文字 |
| 页面 / 分区 | `#FFFFFF` / `#F8FAFC` | 留白与分组 |

强调色适合图形、边框、少量标题；普通文字优先深色，避免小号白字直接压在亮蓝或亮绿上。颜色始终配合形状、位置或标签；虚线若表示可选，应有“可选”文字，不同时表示另一种状态而不解释。

优先用一致的线性矢量图标，例如项目已采用的 Lucide。没有图标资源时使用 draw.io 原生人物、资源库、文档、工具或检查形状，不临时依赖外链图片。图标辅助身份识别，名称必须可读；核心业务隐喻不能改变包含、调用与执行语义。

## 布局与文字

先选主线，再选横向、分层、辐射、卡片或左右对比布局。相同职责同尺寸，对齐同级节点，给文字和连线留空间；不要用网状箭头代替分组。层次本身可说明包含，但不能抹掉真实安全边界。

模板以 1280×720 为起点，标题约 30–34、节点约 20–24、辅助约 16–18；这是可调整的起点，不是所有图的强制阈值。按最终投影、正文或手机尺寸检查；太密时删去可下沉说明或拆图，不无限缩小字号。字体使用系统可用的中文字体并设置后备，三层文字足够。

节点用短名称和必要限定，长解释归正文。避免装饰阴影、密集浅矩形、无意义图标和大段边注。检查箭头标签是否压线，不能为了绕线发明中间组件。
