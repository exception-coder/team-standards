# 视觉语言与模板选择

绘图时按本页默认风格起步，项目已有规范和用户明确选择优先。模板中的数字员工仅用于演示表达方法。

## 团队默认风格

2026-10-29，用户审阅改用 draw.io 自带图标后的三套模板、四页预览并确认：“这版可以，后续架构图默认按这套风格绘制”。以下源图及其同源预览是团队后续架构说明图的默认视觉样板，不再把形象化表达视为需要额外提出的选项。

- 构图先突出一个核心主体，再安排支撑资源和辅助说明；用面积、位置、明暗与留白形成主次，避免等大流程框堆叠。
- 优先使用 draw.io 自带图标，默认复用模板的 iOS7 Icons 线性家族与下方对象映射；同图统一家族、描边与视觉尺寸。遇到不适合的业务语义时再选其他同风格自带图形，确无合适素材才按需定制，不默认扩建自建库。
- 沿用下方语义配色、浅分区和短标签；图标辅助识别，文字说明业务含义。可选、规划和校验边界继续显式表达。
- 保留原生节点、图标、文字与连接器；图标可移动、缩放、改色，源图与导出预览一致。

该默认约定适用于团队架构说明图，不扩展为 Web UI 或业务统计图表的风格要求。已有项目规范和用户指定优先；标准 ER、时序、状态与部署图按其专业符号绘制，可复用配色和文字层级，不强套信息图构图。

## 配色与形态

| 语义 | 默认强调色 | 用法 |
|---|---|---|
| 核心主体 | `#2563EB` | 主要能力或系统；小面积实色主体配白字 |
| 方法 / 智能能力 | `#7C3AED` | 方法资源、模型规划；标签继续区分语义 |
| 业务资源 / 成果 | `#0D9488` | 知识、工具、入口或成果；标签区分对象，不凭绿色宣称已实现 |
| 控制 | `#B45309` | 权限、程序校验与风险关卡 |
| 正文 / 辅助 | `#14213D` / `#66758B` | 浅色背景上的文字 |
| 页面 / 分区 | `#FFFFFF` / `#F8FAFC` | 留白与分组 |

优先区分三层：核心主体用较大面积与实色或清晰边界；支撑对象用浅底、统一图标和深色短标签；说明与可选扩展用低视觉权重。缩成缩略图时应仍看得出主角和阅读路径；不要求所有图都出现实色大圆或照搬模板比例。浅底常用 `#EFF6FF`、`#F5F3FF`、`#ECFDF5`、`#FFFBEB`。

强调色适合图形、边框和核心主体；普通文字优先深色。颜色始终配合形状、位置或标签；虚线若表示可选，应有“可选”文字，不同时表示另一种状态而不解释。

## 统一图标与语义

优先使用 draw.io 自带图形与图标：先在左侧搜索，必要时打开 More Shapes，选择语义合适且风格一致的一套。项目或用户有明确图标要求时遵从；只有自带素材不合适且确有特殊业务表达需要时才定制，不为“原生可编辑”默认重画一套。

当前三套模板及无其他图标约定的新图默认采用自带 **iOS7 Icons** 线性家族，统一描边、颜色和视觉大小，并保留图标本身比例。以下名称已在实际编辑器中渲染核实；已有项目图标规范优先，语义不适合时按上方选择原则调整。

| 对象 | 自带图形名 | 模板中的 shape 标识 |
|---|---|---|
| 人员 / 数字员工 | User | `mxgraph.ios7.icons.user` |
| 工作能力 / Skill | Cube | `mxgraph.ios7.icons.cube` |
| Prompt | Chat | `mxgraph.ios7.icons.chat` |
| 知识 | Book | `mxgraph.ios7.icons.book` |
| Tool / 执行 | Tools | `mxgraph.ios7.icons.tools` |
| SOP / 用户任务 | Documents | `mxgraph.ios7.icons.documents` |
| 权限与程序校验 | Locked | `mxgraph.ios7.icons.locked` |
| 模型规划 | Lightbulb | `mxgraph.ios7.icons.lightbulb` |
| 业务入口 | Window | `mxgraph.ios7.icons.window` |
| 成果 | Document | `mxgraph.ios7.icons.document` |
| 可选协作 | Share | `mxgraph.ios7.icons.share` |
| 拒绝执行 | Delete | `mxgraph.ios7.icons.delete` |

图标辅助识别，业务名称与限定必须保留；锁不意味着校验必定通过，灯泡不代表模型能够自行授权执行，分享符号不代表协作已经实现。不能为了凑图标虚构组件或流程。

“自带”和“自建”须明确区分。4.15.1 的 [13 项自建原生图标](../assets/native-icon-library.xml)由基础图元组合，保留为兼容与特殊拆分需求的备用，当前模板不使用，也不是 draw.io 官方自带图库。内置 stencil 可按图形编辑，不把每一笔都能取消组合作为默认验收条件。

## 布局与文字

先选主线，再选横向、分层、辐射、卡片或左右对比布局。相同职责同尺寸，不同职责按信息权重区分；避免所有节点等大、等深、等边框。对齐同级节点，给文字和连线留空间；不要用网状箭头代替分组。层次本身可说明包含，但不能抹掉真实安全边界。

模板以 1600×900 为起点，标题约 40、核心主体约 32–36、节点约 24–28、辅助约 18–20；这是可调整的起点，不是所有图的强制阈值。按最终投影、正文或手机尺寸检查；太密时删去可下沉说明或拆图，不无限缩小字号。字体使用系统可用的中文字体并设置后备，三层文字足够。通常两层的限制针对可见业务容器；图标内部的技术分组不算架构层级，也不计入主节点数量。

节点用短名称和必要限定，长解释归正文。避免装饰阴影、密集浅矩形、无意义图标和大段边注。检查箭头标签是否压线，不能为了绕线发明中间组件。
