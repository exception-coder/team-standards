# 注释规范

## 语言

注释使用当前会话沟通语言；团队或项目另有明确约定时服从项目约定。

## 按信息需要编写

- 类或文件：名称无法说明职责和边界时补充说明，不要求每个类都有注释。
- 方法或函数：公共契约按语言惯例说明参数含义、结果与失败条件；已由继承文档或名称清楚表达的内容不重复。
- 核心代码块：仅在逻辑不显然时解释原因，长度以准确表达为准，不用固定行数截断必要说明。

字段注释仅用于名称无法完整表达的单位、范围、来源或兼容约束。

## 禁止

- `v2 新增`、`本次修改`、`2026-xx-xx 调整` 等版本日志。
- 复述代码、逐行翻译、废话、被注释掉的死代码。
- 在函数头复制整份设计或调用链；应链接唯一来源。
- `[ADDED]`、`[CHANGED]`、`[DEPRECATED]` 等提交过程标签，除非语言或公开 API 的正式弃用机制要求。

保留法律声明、协议生效日期、仍有效的兼容原因及上游缺陷引用；日期和工单号不是删除依据。Hook 的模式匹配默认只提醒，由人或 Agent 结合用途判断。

修改代码时同步清理触及范围内已失效、误导或重复 Git 流水的注释，不扩大为无关的全文件治理。
