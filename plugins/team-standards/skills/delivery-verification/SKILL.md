# 交付验证引导

帮助 Agent 选择能证明当前改动有效的检查，并清楚说明实际结果。插件不注册 Stop 验证门禁，不要求每次任务获得 Forge PASS、记录治理 JSON 或执行固定的 phase=all。

## 工作方法

1. 根据本轮实际改动和相关依赖选择验证范围，保护他人的未提交内容。优先复用项目现有测试、构建和检查命令。
2. 执行与风险相称的验证。只改说明通常检查链接与事实；局部代码运行相关测试和必要构建；影响共享运行库、装配时核对消费者并扩到对应风险。范围不明先补影响证据，再说明必要扩展，不能仅因调用了本 Skill 就要求全仓测试。
3. 检查失败时分析原因并修复已授权范围内的问题。相同环境或工具错误没有新线索时停止重复尝试，记录缺口和恢复方法，继续可完成的工作。
4. 验证后只有相关输入改变才重跑受影响检查；无关修改、提交或单纯补充说明不自动废弃已有结果。
5. 同步受影响文档并遵从项目提交约定。回复中说明改了什么、做了哪些验证、结果及尚未验证的内容；失败、受阻或未完成也可以正常结束会话并报告真实状态。

## 执行范围与证据复用

- 日常迭代优先快速、可靠的定向反馈；按实际准备成本与风险区分普通回归、数据库/容器、浏览器、跨系统和发布验收，复用原生标签、项目、profile 与过滤器。快而窄的集成用例可以进入快速套件；昂贵准备按本次风险选择，必要权限、事务、状态、协议和迁移证据不能后置。项目已有人工验收/编码优先策略时消费其授权，不自动启动重验证。
- 区分依赖构建、测试源码编译、环境准备和用例执行范围；Surefire/JUnit 的执行过滤不保证 javac 只编译所选测试。编译阻断先核对实际工具链（Java 项目看 mvn -version）、源码、依赖制品和最小基线，再归因；未改过测试文件不是无关证明。隔离单例通过不代替宿主完整资源和装配检查。
- 开始昂贵检查前用现有记录说明所覆盖风险、命令及承接阶段；已有日志可记录总耗时、准备成本和重复次数，不另建统计平台、配额或时间门禁。证据充分且相关输入未变即结束验证；超出反馈目标时优化范围和准备，不通过跳过必要风险来达标。

- 按实际影响选择系统、模块、用例和必要消费者；全量验证需要具体影响依据、明确授权或项目已采用的强制门禁。根 POM 登记模块本身不足以触发全仓回归。
- task 完成、提交、模型轮次、Forge 进度回报和归档本身不触发重验。核对证据覆盖即可，不能机械生成第二轮验收命令。
- 先读实际构建脚本和生命周期：构建已执行的类型、静态或测试检查计入证据，外层不重复运行同范围同输入的检查。构建未执行的业务风险仍需验证；构建失败时区分已通过子检查与失败阶段，不将整体标为通过。
- 只有证据覆盖的代码、测试、配置、依赖及相关环境输入未变，且结果可追溯到当前交付范围时才复用。无需另建指纹平台；不同命令名不证明执行不同，相同命令也不证明输入相同。未发现测试、全跳过或环境失效不算有效覆盖。
- 公共协议、安全或迁移输入变化时，重新验证对应风险及受影响消费者。并行改动影响输入时，核对准确快照，必要时隔离验证；不把他人修改认领为本次证据，也不把历史 PASS 套给新输入。
- 明确采用 Forge/CI 的项目继续消费其真实证据协议；失效需重新绑定或登记时按协议处理，但不能由指纹失效直接推导全仓测试。现有强制范围有冲突时指出来源与影响，不静默绕过。

## 范围选择示例

| 场景 | 最小充分范围 | 不能据此得出的结论 |
|---|---|---|
| 独立 Web Starter，根 POM 新登记模块 | 新模块、必要依赖及 Reactor 解析；使用项目支持的 Maven 模块能力，区分依赖构建与依赖测试 | 不能仅因 POM 变化追加业务前端全套测试；装配或共享契约另有影响时补对应消费者 |
| 公共 HTTP 协议变化 | HTTP 行为、401/403、字段校验、204、SDK 兼容及关键消费者；按实际协议影响覆盖 | 不能仅跑改动文件；`related` 的静态关联可能漏掉动态消费者，须结合调用证据补齐 |

测试资产新增与准备复用见 [测试资产与原生工具](../coding-standards-common/references/testing-assets.md)。这两例用于审阅计划的范围与覆盖，不要求新建两套脚本或机械增加测试配额。

## 结果含义

- 测试通过只证明被执行场景，构建通过不代表业务验收或已上线。
- 未运行、环境不可用、测试失败分别说明，不伪造 PASS，也不把缺少机器登记当成代码不合格。
- 不要求为简单修改另建验证报告、审阅文档或证据账本；命令输出、现有测试及提交说明可承载适当证据。
- 无法验证时可以交付已完成部分及具体限制，但不能声称全部验收通过。是否提交、合并或部署按用户授权及项目规则判断。

## 可选集成

只有项目明确采用 Forge、状态契约或兼容治理时，才读取相应配置与 [执行适配协议](../change-readiness/references/execution-adapter.md)、[治理检查器协议](../change-readiness/references/governance-checker.md)。工具存在不自动触发绑定、record、preflight 或 delivery；独立 CI/宿主门禁仍由项目负责。

设计维护继续按 [change-readiness](../change-readiness/SKILL.md) 的影响范围进行；文档归属见 [markdown-writing-standards](../markdown-writing-standards/SKILL.md)。这些引导不授予部署、归档或外部写入权限。
