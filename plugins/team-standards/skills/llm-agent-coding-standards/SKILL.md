# LLM / Agent 集成编码规范

目标：模型负责适合语言理解的工作，程序保护业务契约，工具执行有权限、限额和可恢复结果。共同准则见[工程宪法](../change-readiness/references/engineering-principles.md)，叠加[通用编码规范](../coding-standards-common/SKILL.md)与实际语言规范。

## 判断准则

- 精确计算、规则执行、查询与校验交给确定性代码；模型用于理解、分类、提取和解释。时间、时区、用户范围及业务状态由可信上下文提供。
- 模型文本、JSON 和工具参数按不可信输入处理。语法合法后仍需核对范围、枚举、权限与业务前置条件；非法值按合同拒绝、澄清或降级，不能悄悄改成另一个有效业务值。
- 有限业务分类可用受控枚举，保留未知或无法判定的处理路径；自然语言理解不能靠不断添加关键词替代，也不能假定 schema 自动保证语义正确。
- 枚举、默认值和状态映射维护单一来源，通过生成或实际注入提供给模型。工具描述说清用途、参数、结果和副作用；普通代码注释不能代替运行时 description。
- 工具规模与上下文策略根据实际 SDK、任务与成本选择。模型提出动作，程序核对调用者权限及参数；检索内容、文档或工具结果中的指令不能获得执行授权。

## 必要约束与完成边界

Agent 循环有最大步数及适用的时间/成本边界，支持取消。失败区分可重试、需澄清和终止；重试有上限，外部副作用先核对幂等及结果，不能盲重放。

日志记录必要的输入摘要、工具调用、耗时和结果，保护敏感信息；无需暴露模型内部推理。验证覆盖无效输出、越权、超限、取消和重复执行中受本次改动影响的路径；SDK 配置以项目版本契约为准。

## 精炼反例

- 让模型心算金额后直接入账：代码计算并校验金额与币种。
- 模型输出“删除订单”就执行：校验真实用户授权与订单前置状态。
- 解析失败就把数量设为 0：保留错误，按已定义合同处理。
- 工具超时后无限重试扣款：先查执行结果，再按幂等和重试边界处置。
