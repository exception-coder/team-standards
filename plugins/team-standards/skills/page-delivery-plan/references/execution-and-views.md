# 计划执行与视图

## 实施时使用

读取最新主清单和对应项目任务，先核实已有实现，再选择前置满足的一项。每项有明确交付负责人，执行者可以是人或 AI。用户只要求计划时，不额外生成领取、交接和验证表格。

进入实施后在原任务中记录实际进展、剩余工作、阻塞、提交与验证证据、下一步动作。沿用项目状态；无约定时可用待明确、可开工、进行中、待验收、已验收。前置未满足或只完成局部时保留剩余范围，不把整项标为完成。

按页面实际入口核对保存结果、数据可见范围、必要的重复操作和失败恢复。具体场景随实现风险选择，不把通用检查逐条抄进计划。演示、Mock、真实接口和上线结果分别如实记录，不能用缩减完成标准代替交付。

## 一个主清单，多种视图

- 沿用项目已有 OpenSpec、任务平台或计划文档。没有载体时维护一份 Markdown；详细设计引用所属正文。
- 图表达主要页面和流程。调整范围后更新相关节点及同源预览，不在图上维护动态状态。
- Excel 默认导出同一张简明功能表，保留编号、版本和来源。确有独立阅读用途再加工作表；不要自动添加批次表、确认表和说明页。
- 有原型时按主 Skill 的截图规则在功能行嵌入真实缩略图，附完整截图链接。表格筛选或排序后核对图片仍对应原功能，不能只检查文件中有图片。若工具无法让图片跟随排序，明确说明限制并保留稳定编号和原图链接。
- 用户指定 Excel 为主清单时直接遵从。其他情况下，表格修改先按编号回写主清单再导出，不承诺未经实现的自动同步。
- 原有条目合并时保留编号对应关系，放在简短变更记录或折叠说明即可，不让历史编号占据主视图。
- 导出后核对范围、中文、筛选和链接，渲染检查可读性。状态与实际验证结果保持一致。

## 粒度示例

“待办详情”可以一行写清调整、确认、忽略和执行反馈，完成标准是处理结果保存且可重读。只有各部分确需独立交付时才拆行。接口与存储由该业务结果承接，不另列“公共待办能力”。

同一规则适用于多个页面时只说明一次，例如“销售看本人，经理看所管团队”。中台登录及菜单、资源权限不重复进入业务页面计划。

## 方法依据

按用户活动组织全景、按可完成的目标安排交付，参考[用户故事地图](https://www.jpattonassociates.com/wp-content/uploads/2015/03/story_mapping.pdf)。任务状态、真实验收与续接参考[长任务 Agent 实践](https://www.anthropic.com/research/effective-harnesses-for-long-running-agents)。同一任务的多视图参考[GitHub Projects](https://docs.github.com/en/issues/planning-and-tracking-with-projects/learning-about-projects/about-projects)。按项目需要采用，不扩成固定文档配额。
