# 交互设计模式

用于新增业务页面、交互重构、页面复杂/操作繁琐反馈、表单/审批/搜索/筛选/导航优化，以及设备适配涉及的任务流程变化。由 `frontend-excellence` 统一承接，不另注册 interaction-design 同职责 Skill。

纯颜色、字体、间距、简单文案、无交互变化的样式修复、后端开发及依赖升级不展开本模式。评审默认只读；实现仍以用户授权为准。项目已有同职责 Skill/规则时以项目版本为主，同一任务只分析一次；语义优先不表示宿主已物理去重。

## 从任务到最小实现

先读项目适用规范和[交互宪法](interaction-constitution.md)。复用已有业务事实与任务上下文，按缺口采用以下方法，不要求固定七步、额外报告或向用户逐项提问：

- **任务与决策：**确认角色、目标、频率和使用环境，找出用户需要知道、决定、执行什么。根据当前任务区分 P0/P1/P2；只保留完成决定所需的信息。
- **现状复杂度：**沿真实任务路径找重复信息、按钮、字段、输入、跳转及确认。保留必要业务和风险控制；先消除冗余，再选容器，不能只把复杂度装进更多卡片或弹层。
- **交互选择：**依据比较需求、输入规模、是否需保持上下文和操作后果，选用下表模式；没有一种组件天然更简单。
- **反馈与异常：**按实际影响覆盖加载、空结果、处理中、成功、校验失败、权限不足、不可用及恢复；细节复用[状态与恢复](interaction-and-states.md)，不重复定义状态清单。
- **最小实现：**复用项目组件、视觉规范、移动端规则及已有状态管理，不因本模式引入新框架、通用流程引擎或重复设计系统。
- **验证：**使用现有浏览器、测试和任务证据，检查主要操作能否被识别、任务能否完成、结果能否理解、错误能否恢复。原输入未变的证据继续复用。

## 按任务选择模式

| 任务特征 | 优先考虑 | 需要核对 |
|---|---|---|
| 多对象、多维度比较 | 表格或结构一致的列表 | 比较字段在同一视野；移动端保留关键差异，不把每个字段变成卡片 |
| 少量对象的独立概览 | 列表或卡片 | 卡片边界有业务含义；避免多层容器和装饰占据首屏 |
| 单对象局部、可恢复修改 | 行内编辑或就地操作 | 保存/取消、错误、键盘操作与输入保留明确 |
| 大量相互依赖的输入 | 连贯表单；有真实阶段依赖时再分步 | 不用步骤隐藏过长表单；保留进度和返回后的输入 |
| 审批、比价等业务决策 | 关键依据与决策动作相邻 | 展示差异、权限和影响；重大决定不为少一次点击取消保护 |
| 列表旁查看详情或局部补充 | 抽屉、侧面板或详情页 | 空间足够、上下文保留；窄屏必要时改详情页，避免抽屉套弹窗 |
| 必须暂时聚焦的选择或风险确认 | 弹窗 | 目的明确、能退出、焦点恢复；不把普通状态反馈都做成弹窗 |
| 搜索、筛选与导航 | 常用条件直达，低频条件渐进展开 | 当前范围和已选条件可见，可清除；返回后保留有用上下文 |
| 高频重复作业 | 连续或批量操作 | 范围、权限、部分失败及恢复可理解；触摸和键盘都能完成核心任务 |

## 关键任务验证

复用[质量验证](quality-gates.md)，在既有证据中回答六个问题即可：页面目的是否清楚；主操作是否突出；信息和操作有无冗余；跳转/输入/确认是否必要；反馈与恢复是否明确；目标设备和真实业务场景是否可用。

对改造任务比较同一角色、同一任务与等价数据下的改前/改后路径，说明实际消除了哪些理解、决策、操作负担，必要风险控制是否仍有效。优先检查主要路径和受影响异常，不以截图更美、组件更少或编译通过宣称体验改善。没有可运行页面时报告规则/实现审读结果和待验收项，不补造用户行为证据。

### 校准案例（不是已验收页面）

- **采购报价审批：**用户需要比较可比报价、交期及审批依据后作决定。先核实币种、税费/口径和权限；突出差异及审批动作，低频管理收纳。不能只重排按钮，也不能隐藏风险或把不同比较口径混为一谈。
- **样衣管理：**围绕已确认的状态、位置和当前可执行动作组织信息；技术属性按需展开。保留业务状态迁移与权限限制，不把所有动作无条件展示，不为每个字段造卡片。
- **纯后端 API 修改或只改按钮颜色：**不启动完整交互设计；前者用后端规则，后者按现有视觉规范处理。如果业务行为或可访问性实际发生变化，再评估受影响交互。
