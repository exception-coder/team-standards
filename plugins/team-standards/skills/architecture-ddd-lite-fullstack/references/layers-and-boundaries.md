# 分层与边界速查

## 层职责

- Presentation：协议、路由、输入校验、展示状态和结果映射。
- Application：用例入口、流程编排、事务协调和权限上下文。
- Domain：实体、值对象、领域服务、策略、业务不变量和 Repository 端口。
- Infrastructure：数据库、消息、缓存、外部服务和框架适配。

## Feature 结构

优先在 feature 内组织 presentation/application/domain/infrastructure。只有真正跨 feature 稳定复用的能力才提升到共享模块。

## 聚合判断

围绕一致性边界判断对象是否属于同一聚合：是否必须同事务提交、是否共享不变量、是否允许独立生命周期、是否有独立身份、失败时是否需要独立补偿。跨聚合编排放 application，不把一个聚合内部状态直接暴露给另一个聚合修改。

## 原子能力

一个能力应表达一个稳定业务动作，输入输出清晰、可单测、无隐藏跨场景分支。不同业务场景的规则明显不同时拆分能力，由用例层选择。
