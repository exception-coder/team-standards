# 按需沉淀现状理解

默认在会话中交付结论、当前证据和缺口。仅当用户要求文档、项目明确要求或需要长期重构基线时持久化。

1. 优先补充已有相关文档；确需新建时使用项目约定，未约定则在仓内 `docs/architecture/{module}.md` 保存一份说明。
2. 只保留范围、关键行为和边界、难以从代码直接恢复的约束、风险及证据来源。注明对应提交或观察时点及覆盖缺口，不宣称永久有效。
3. 当前调用关系由新鲜 Graphify 查询并用源码核实；已接受行为引用 OpenSpec，业务术语和不变量引用领域知识。推断与待确认项单独标明。
4. 不生成配套 `-ai-ref.md`，不抄整段核心代码、完整文件树或逐方法索引。图表仅在有助理解复杂边界时使用，不强制三张图。
5. 实施过程中仅同步受影响的长期知识，瞬时查询结果不转成固定文档。不重复建设 00–10 文档树或个人目录索引。
6. Markdown 和导航按 [文档归属规则](../../markdown-writing-standards/references/document-index-workflow.md) 核对；历史梳理文件保留，不无条件覆盖或删除。
