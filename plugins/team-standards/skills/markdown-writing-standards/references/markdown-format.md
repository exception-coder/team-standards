# Markdown 与 Mermaid 格式细则

目标：文档结构清楚、引用有效，图表在目标阅读环境中可渲染、可理解。共同准则见[工程宪法](../../change-readiness/references/engineering-principles.md)；按当前改动选用以下要求。

## 文档结构

- 标题按语义分层，保持层级连续和同级命名一致；沿用项目编号约定，避免重复标题使引用含糊。
- 重组章节时核对受影响目录、锚点及“见第 N 节”等引用。长文或多读者路径需要导航时添加，不按章节数量自动生成目录。
- 表格用于比较和字段映射，列表用于并列或顺序动作；表头有分隔行、各行列数一致，内容过长时改为段落或独立说明。
- 标题、列表、表格和代码块之间保留适当空行；分隔线仅在有助于分组时使用。
- 围栏闭合并标明语言，纯文本用 text。代码示例明确是可运行片段还是示意，不为了形式补无关导入或行号。

## Mermaid 的必要约束

- 以项目实际 Mermaid 版本、宿主配置和渲染结果为准；新语法先核对适用版本，不复制静态“所有宿主都支持”表。
- ID 使用稳定且简单的标识，显示名承担业务含义；流程图中含 Unicode 或语法敏感字符的文本使用合适引号。subgraph 的 ID 与标题分开，控制块配对闭合。
- mindmap 的缩进清楚表达层级；时序图的参与者、别名和消息各自遵循语法。换行、转义、图标与样式按具体图种和宿主核实，见[语法入口](../mermaid-syntax-ref.md)。
- Emoji 是否可用还涉及字体与宿主；关键语义由文字承载。不要把某环境的显示问题写成解析器永久禁令。
- 新增或实质修改图表，使用已有解析/渲染工具检查，并在实际使用尺寸查看标签、连线、遮挡与裁切。没有渲染条件时明确缺口，不能把围栏检查称为渲染通过。

## 精炼反例

| 做法 | 判断 |
|---|---|
| 图很小就省去语法与可读性检查 | 检查与尺寸无关，按实际图种验证 |
| 为缩短标题删除关键条件 | 保留准确含义，细节可放邻近正文 |
| 把一次换行失败推广为所有图种不支持 | 核对具体版本与图种 |
| 每逢八个章节强制新增导航 | 按阅读路径和查找需要选择 |
| 章节改名后只检查文件路径 | 同时核对锚点与文字引用 |

图要表达什么由设计或业务 Skill 决定；本文件负责格式与可读性，不代替对象关系或业务规则审读。
