# 领域规格的证据核对

先从项目现有业务文档、OpenSpec 和设计查已确认规则，再用代码、DDL 和运行记录核对对象、状态、关联及下一动作。没有已有载体且需要长期保存时写入项目 docs/domain；同主题不复制两份。

## 事实与候选

- **已观察**：能定位到代码、DDL、查询、日志或测试结果，只证明该范围内的实现/运行事实。
- **推断/候选**：由事实推导的业务解释，保留来源、反例和待确认问题。
- **已确认**：经过项目正常业务评审的规则；迁移资料或生成文档不会自动升级到此状态。

## 按任务核对

1. 明确业务对象、标识、前后状态、旧关联和下一动作。
2. 使用 Graphify 缩小源码范围，必要时读取精确实现；表字段以项目迁移或实际 Schema 核对。
3. 在授权范围内只读取必要运行证据，不保存凭据和无关业务载荷。
4. 核对失败、重复操作、回滚及下一业务动作，列出冲突与未取得的证据。
5. 复用项目已采用的分析工具；没有挖掘工具时按证据核对即可，不安装独立知识服务、不伪造挖掘结果。
6. 按项目规则更新原规格或业务文档，代码改动与相关知识一起提交。

只在业务状态或规则存在缺口时展开；纯展示和已有规则完整覆盖的小改不需要额外候选报告。缺少运行证据时明确边界，不把接口成功当作业务终态已验证。
