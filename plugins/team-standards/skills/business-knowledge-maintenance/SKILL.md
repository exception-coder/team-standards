# 业务知识维护

目标：让人和 AI 从同一份项目文档理解业务。Markdown 是唯一维护正文，YAML 描述归属、关联和可信度；向量索引、知识图谱都是可重建产物，不另建知识工程。

## 何时维护

- 术语含义、规则、流程、用户可见能力、业务接口语义或数据范围改变时，更新对应章节；新增字段只在改变业务含义时更新。
- CSS、SQL 性能、技术绑定或内部重构且业务行为不变时，不生成知识文档。纠正已发现的文档事实错误可原位修改。
- 优先复用已核实的任务证据，通过定向搜索、LSP（可用时）、Git 与必要源码查缺口。Graphify 只作已采用项目的复杂关系辅助，不因文档维护自动建图。

## 一份正文

先读项目 AGENTS 和现有文档索引，按主题或 ID 找原文，再更新受影响段落。已有业务设计或 OpenSpec 已完整定义该主题时，链接它，不再抄一份 rules.md；不强制把现有格式改成新格式。

无既有归属时，默认 `docs/domain/<业务模块>/`。已有模块内 `docs/knowledge/` 或 `docs/business/` 的项目继续沿用；不因目录偏好迁移资料。跨模块规则选一个所属位置，消费者只链接。项目之间也只引用来源项目。

按实际内容选择概览、术语、规则、流程、能力五类，建议文件名为 `overview.md`、`glossary.md`、`rules.md`、`flows.md`、`capabilities.md`；不是必填五件套，短主题可以合并，旧文件名和 ID 保留。

| 内容 | 需要讲清楚 |
|---|---|
| 概览 | 谁用、解决什么问题、核心对象与主要能力 |
| 术语 | 业务定义与已确认别名；不自行推断同义词 |
| 规则 | 触发场景、条件、结果、失败或例外；未知处标待确认 |
| 流程 | 参与者、主要步骤、状态变化和失败后下一动作 |
| 能力 | 业务输入、返回、限制与数据范围；不绑定具体 MCP 名称 |

正文面向业务读者，不把类名、字段或 API 路径复制成业务解释；必要实现证据只保留简短定位。正式概览或复杂流程配一张全景图时优先 draw.io 源图与同源预览，图旁保留可检索的文字；不要求每条规则都画图。

## 轻量元数据

新建独立知识文件采用以下最小字段，`related` 有实际关联才写，不能编造证据或日期：

```yaml
---
id: sample-visibility-rules
domain: sample-management
type: rules
knowledge_status: inferred
updated_at: 2026-11-07
related: [sample-query-capabilities]
---
```

- `id` 是稳定标识；改文件名也保留。`type` 使用 overview/glossary/rules/flows/capabilities；旧类型可继续使用，不全量重分类。
- `knowledge_status`：`verified` 有业务确认或已接受规格依据；`inferred` 由代码推断或待核对；`deprecated` 已失效。代码和测试通过不等于业务确认；无依据不升级可信度。
- `verified` 内容保留确认来源或已接受规格的可定位引用及日期；废弃内容注明原因，有替代文档则链接。不额外引入 version/status 审批字段。
- 旧 `stability: stable/draft` 与已有元数据继续保留；没有确认依据时，不把 stable 自动换成 verified。触及时再补可信度，混合可信度先拆段或明确标记，不把整篇推断当正式规则。
- 只有内容、可信度或来源变化才更新日期，不为“同步”空改文件。
- 同一文件混合已确认与待确认内容时，文件级标 inferred，段落保留各自可信度及来源；不支持段落可信度的检索器不得把整篇作为正式答案。确需独立检索时再拆开相关段落，正文仍只保留一处。

## 完成前核对

确认正文与已接受需求及已实现行为一致，未知项有标记，关联 ID/链接可定位，同一规则没有第二份正文。修改已确认规则但尚未取得确认时，只把变更部分标为 inferred，保留原依据并写明冲突；不擅自改变其他规则的可信度。

随本次代码或文档变更提交，不增加强制审批、Hook、独立知识仓、空目录或全库扫描。只报告实际更新的主题和待确认项。

## 后续检索边界

现在直接检索 Markdown 即可；需要问答时再接 RAG，不预装数据库、索引服务、LightRAG 或 Agent 框架。索引按标题和语义分块，携带文档 ID、来源段落、可信度与 Git 提交/内容哈希，变更或删除后可重建、撤销旧块。

正式业务咨询默认仅检索有确认依据且未废弃的内容，inferred 只用于明确的内部核对；旧资料未完成可信度核验前不默认公开。检索范围沿用项目已有的数据访问范围，索引不是授权来源。实时余额、状态、库存等通过已有业务 API/MCP 查询，不把文档快照当实时结果。
