# 库表设计

把数据所有权、业务约束和访问场景落到可实现、可审核的模型及演进方案。按[工程设计输出规则](../change-readiness/references/engineering-design-output.md)裁剪深度。

## 从访问场景到结构

- 明确业务对象、数据归属、生命周期、关键读写、事务和必须保持的不变量。对涉及的现有表与约束，用[后端证据](../backend-evidence/SKILL.md)核对目标环境元数据或可追溯 DDL、迁移版本与读写消费者。只有仓库证据时标出版本和覆盖，目标环境未核实则保留差异风险。实体类或 Mapper 只能证明代码映射。
- 新表、关联表和历史表应对应当前业务、生命周期或必要约束；先评估现有记录能否承载，不为假设的扩展提前建表。多值、独立生命周期、查询与完整性等有实际需要时可独立建表；精简已有表前核对消费者、数据迁移和兼容，不以表少为目标。
- 概设使用[概念设计模板](assets/conceptual-design.md)，描述核心实体、关系基数、生命周期与关键约束。ER 图聚焦相关实体及关联，逻辑关系和实际外键分别标明。简单局部变更可用现有模型引用或文字。
- 详设使用[详细设计模板](assets/detailed-design.md)。每个受影响字段写业务含义和物理定义，状态、类型、标志写值域及对行为的影响。标明目标引擎、版本或方言及影响兼容的能力。选定约束落点，说明既有数据和并发写入怎样保持唯一性、完整性或其他不变量。
- 按真实查询或可追溯的目标访问场景论证索引。关联过滤、JOIN、排序、分页、组合列顺序和预期数据规模，核对已有索引、写入成本及验证方式。实测数据、估算和待确认项分别记录。
- 给受影响结构写清演进路径。新库说明建库、初始化及验证。存量变化核对前置数据、依赖方、新旧版本读写兼容、DDL/DML 顺序、回填及失败恢复。涉及大表、并发回填、长锁或不可逆步骤时，细化批次、进度、观测、停止条件及可行的恢复或前滚路径。

## 交付自检

- 核对实体、关系、字段、约束和读写路径能互相对应。示例 SQL、待运行脚本和已在匹配版本环境执行的结果分别标注。
- 验收按影响覆盖结构、约束正反例、核心 SQL 与执行计划、迁移前后数据一致性及失败恢复。对尚无证据的性能、目标环境或历史数据分布保留验证项。
- 与[技术实现设计](../technical-implementation-design/SKILL.md)组合时，物理表结构和迁移步骤归本设计，应用调用与发布编排引用这里的数据库契约。
