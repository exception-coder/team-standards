# 设计文档工作流

开发任务自动执行[发现、补建、绑定与交付同步](automatic-design-maintenance.md)，不以 JSON 存在为前置条件。脚本负责安全合并，Agent 负责真实业务内容；只读任务不写入。

## 唯一载体

“唯一”按职责判断：模块当前概设/详设是现状基线，活动 change 是独立目标增量，二者应互相引用而非复制。不能以去重为由拒绝维护当前设计，也不能让整个模块永久追加到一个 change。绑定与同步遵循 [当前设计基线协议](current-design-baseline.md)。

1. 先读项目约定和已有相关设计；历史文件可作为证据核对，不按文件名推定仍有效。
2. 已启用 OpenSpec：以官方 CLI 返回的活动 schema 和实际工件路径维护本次设计、任务及行为变更，不额外建立同主题设计副本。
3. 未启用 OpenSpec：优先更新现有设计。确需新增时在仓库 `docs/design/{feature}.md` 维护一份说明；用户或项目指定其他位置时遵从。
4. 档位决定需要覆盖的风险与细节，不决定文件数量。模板只是按需提纲，不要求填写全部章节或图表。

## 最小内容

说明目标、范围、关键取舍、受影响契约及验证方式；高风险变更补充迁移、兼容与回滚。API、数据和状态说明复用已有权威契约，必要内容放在同一设计的相关章节，不另写摘要副本。

实施坐标通过新鲜 Graphify、定向源码和当前差异定位，在任务中引用必要文件与符号；不生成独立 `-coding.md`，不复制方法实现和易失效的行号清单。

## 维护与交付

实现发现设计不符时更新唯一载体。现有稳定架构、ADR、运维手册和用户文档若受影响仍须同步；OpenSpec 不是禁止这些长期资产的理由。

不默认创建个人 `ai-docs` 索引树、编号 00–10 文档树、连续版本文件或快照。已有历史资料不批量迁移或删除，确有独有知识时保留其权威归属。已有授权覆盖实施时连续推进，不因文档阶段重复确认。
