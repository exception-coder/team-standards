# 样衣使用工作区概要设计

## 一页总览

样衣使用工作区服务需要查找、领用、临时借用和归还样衣的普通员工。它解决“样衣在哪里、我能不能用、由谁保管、怎样交还”的协作问题。员工在电脑或手机查找可见样衣，查看资料与图片，完成本人领借还；管理员维护档案与授权，管理能力不混入普通员工入口。

核心能力是 **GS-001 可见样衣查阅**和 **GS-002 本人领借还**。预期价值是让样衣流转责任清楚、减少越权和重复处理；查找耗时、归还及时率及收益目标均待产品负责人依据实际业务数据确认，不宣称已有量化改善。

当前交付状态：依据 Yoooni One 提交 `21392f8b0c76e2e1d636ad4594fd481ca77ad70d` 的设计、主规格和服务实现，两个能力已有实现；本次未执行业务回归、未核验发布记录，因此本示例按“实现中（待补验证证据）”呈现，不升级为已验证或已上线。本文是套件业务写作示例，项目权威正文仍在原仓库；迁移与阅读验收另行开展。

## 业务背景与目标

样衣是多人共享的实物。只展示档案不能解决取用与归还的责任问题，允许普通员工使用管理接口又会扩大修改和跨人操作权限。因此工作区把“看得见哪些样衣”和“能对样衣做什么”分别约束。

可验收目标：员工只看到服务端授权范围；本人可对符合状态约束的样衣领借还；冲突和重复请求不重复改变业务事实；电脑与手机获得相同的授权结果。业务效果指标的统计口径、观察周期和目标值待产品负责人确认。测试通过率是工程验收证据，不代替业务收益。

## 用户角色与职责

| 角色 | 职责与协作 |
|---|---|
| 普通员工 | 查找授权范围的样衣，为本人领用/借用并归还本人持有的样衣；不能代他人操作 |
| 样衣管理员 | 维护档案、处理需要管理权限的流转异常；管理员仍须遵守状态、并发和审计约束 |
| 可信超级管理员 | 通过治理入口维护资源组授权；扩大读取范围不自动赋予普通员工管理权限 |
| 产品与测试负责人 | 确认业务含义和验收场景，收集实际结果；业务部门确认效果指标 |

## 核心业务流程

员工登录 → 服务端确认身份、组织和授权范围 → 搜索或扫码找到可见样衣 → 查看当前状态及持有人 → 选择本人领用或借用并确认 → 服务端校验权限、版本及状态后记录流转 → 员工收到结果并刷新列表/详情 → 当前本人持有人归还 → 样衣进入规则允许的后续状态。

借用需要应还日期。无权限、状态不允许或版本过期时不改变事实，提示原因；版本冲突后刷新再判断。网络失败先核实结果，再沿同一请求身份安全重试。需要代他人或管理处理时转管理员，不在普通工作区放宽权限。

## 总体方案与系统边界

本工作区属于 Yoooni One 样衣业务模块，随统一应用和前端交付。它拥有样衣查阅与本人动作的业务规则，复用统一身份、目录和资源授权；目录事实不是由客户端提交可信值。业务记录由样衣模块保存，组织目录只读，图片通过对象存储访问并先校验所属样衣权限。

电脑和手机共用服务端范围和动作规则。列表、总数、详情、二维码和图片访问采用一致口径，避免列表隐藏但直接访问仍泄露。详情与动作复用既有保管服务及事务，不另建一套客户端状态机。共享模型、部署与迁移见[详设公共设计](garment-sample-detail.md#公共设计与来源)。

## 关键规则与质量目标

普通账号默认读取当前公共在库、本人/直属组及显式扩展授权范围。未知组织或目录故障不能扩大访问范围；全组读取授权不等于管理权限。不能替同事归还，管理员也不跳过状态、版本、幂等和审计要求。

借用期限、可领借状态和归还前置条件由服务端规则决定；重复成功请求不重复写入。列表与分页总数一致，账号切换隔离缓存。性能预算、可用性目标和告警阈值待项目负责人依据现有部署指标确认；本示例不虚构 SLA 或吞吐结果。
