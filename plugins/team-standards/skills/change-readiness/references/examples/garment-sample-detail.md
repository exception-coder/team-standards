# 样衣使用工作区详细设计

## GS-001 可见样衣查阅

### 功能目的与适用场景

员工查找工作所需样衣，确认资料、图片及当前保管情况。示例状态为实现中：已提交源资料说明存在实现，实际验证及发布证据尚待盘点；不是新增一套业务设计。

### 角色、入口与前置条件

普通员工从样衣工作区或二维码进入。必须完成认证，并获得服务端访问模式与可信组织范围。访问模式读取失败显示重试，不回退管理模式。

### 操作流程、页面交互与结果反馈

进入工作区后加载可见列表；员工搜索、翻页或扫码查看详情和图片。显示加载、空结果、失败重试和范围说明。切换账号清理相关缓存与详情，避免沿用上一人的结果；手机与桌面共用服务端口径。

### 输入输出、字段含义与校验

关键词和分页是业务筛选，不是扩大授权的参数；对象 ID 或扫码目标仅用于定位。返回授权后的列表、总数、详情和图片。具体分页边界和错误协议沿用项目 API 契约，本示例不编造字段名或默认值。

### 业务规则、状态转换与边界条件

可见范围为当前公共在库、本人/直属组及有效显式授权的并集，再与业务筛选取交集。未建档、归档以及无有效绑定标签/READY 批次的记录不可见。查阅不改变样衣状态，也不因为读取成功自动允许领借。

### 操作权限与数据范围

列表、总数、直接 ID、扫码及图片均由服务端执行一致授权。未知 ERP 组织或目录异常拒绝扩大范围。全部组授权只扩大读取，普通员工不能因此进入管理编辑、导出、批量或统计接口。

### 异常、并发、幂等与恢复

加载失败允许重试并保留查询条件；无权限不返回档案或图片。读取本身不写业务事实，因此写入幂等键不适用；读取后发生并发流转时，以动作提交时的版本和权限校验为准。

### 技术实现

访问过滤器限制普通账号接口范围，应用服务显式接收服务端构造的范围，SQL 分页和总数共用范围约束。详情、扫码和图片在读取前执行对象权限检查。数据授权规则及目录解析复用公共能力，样衣公共库存与当前持有人组合规则留在业务模块；共享依赖见[公共设计](#公共设计与来源)。

### 验收场景及验证证据

依据主规格 `sales-sample-access` 的“销售样衣可见范围”和“可信组织及管理员边界”。用两个不同组账号及一件公共在库、一件其他组非公共样衣准备数据：正常账号能查到公共库存；直接 ID/图片/扫码访问越权对象均拒绝；未知组织或目录故障不能回退全量；获得全部组读取权限仍不能修改档案。每次核对列表、总数和详情口径一致。

原始测试记录、环境与发布记录尚未在本次套件作业核验，保持实现中。实际接入时按稳定功能编号逐项关联正式 Scenario、所属 Requirement 和验证证据；不要复制示例为机器 PASS。

## GS-002 本人领借还

### 功能目的与适用场景

员工为本人取用公共在库样衣，短期使用时登记应还日期，使用结束由本人归还，从而明确当前持有人和流转责任。状态为实现中：源代码与主规格已有该行为，本示例未重新执行项目业务验收。

### 角色、入口与前置条件

普通员工从可见样衣详情进入领用、借用或归还。本人身份由认证上下文确定。领借须满足公共在库及既有状态条件；归还须为当前本人持有。详情读到的版本作为动作前置条件，不能仅凭按钮可见认定可以提交。

### 操作流程、页面交互与结果反馈

员工查看样衣状态后选择动作；借用填写应还日期。确认后按钮进入处理中，提交当前版本与幂等键。成功展示操作结果并刷新受影响列表和详情；失败说明原因、保留仍有效输入，允许刷新或重试。不能代同事归还，需要管理处理时联系管理员。手机和桌面执行相同流程及权限，不在客户端放宽状态规则。

### 输入输出、字段含义与校验

| 业务输入/输出 | 含义及校验 |
|---|---|
| 样衣标识 | 目标档案；服务端重新检查可见性和动作权限 |
| 当前版本 | 详情读取时的版本；与数据库当前版本不一致时拒绝并提示刷新 |
| 应还日期 | 借用计划归还日；依据业务时区和领域规则校验，普通员工借用最多 7 天 |
| 幂等键 | 同一动作重试的身份；不能为空，最长 128 字符，入口还绑定可信身份、样衣和动作 |
| 操作人/持有人 | 从可信身份构造，普通员工不能通过输入他人姓名代操作 |
| 操作结果 | 已执行或成功重放的结果；前端据此反馈并刷新查询，不自行推算持有状态 |

具体 HTTP DTO、状态码及日期格式沿用真实接口定义；若需修改，先进入独立 change，不由本文猜测。

### 业务规则、状态转换与边界条件

本人领用或借用只允许符合既有状态约束的公共在库样衣；操作后记录本人和组织归属。归还先确认当前持有人为本人，再执行既有归还转换。档案生命周期、资料完整度和保管状态是不同维度，不能把“二维码已关联”视为可以领借。不可领借状态、非法期限、跨人归还和版本冲突均不改变业务事实。

源规格给出借用最多 7 天，日期下界和业务日边界由领域规则决定；测试须从实际规则取得边界日期，不能凭自然语言推断精确时间点。历史领借快照保留原事实，不因档案授权配置变化而重写。

### 操作权限与数据范围

普通账号只执行本人领用、本人借用及本人当前持有的归还；不能转移、解除或代他人处理。前端隐藏管理操作，服务端直接请求也必须拒绝。全部组读取授权不是管理授权；可信管理员的管理入口仍受状态、版本、幂等和审计约束。本功能不承担授予权限。

### 异常、并发、幂等与恢复

版本过期返回可理解的冲突，员工刷新后重新判断动作，不自动覆盖他人的流转。重复成功请求重放结果，不增加第二条业务流转。网络中断时保留同一请求的幂等身份，先查询/重试确认结果；不能生成新请求绕过不确定结果。数据库或依赖失败遵守既有事务边界，不显示虚假成功。

实现中必须核对并发版本更新与幂等记录的事务原子性，单看前端处理中锁定不足以证明服务端并发安全。本次未核验生产故障恢复效果，不声称已达可靠性指标。

### 技术实现

普通员工入口验证数据范围和本人身份后复用 `CustodyService`。服务依次校验幂等键、读取成功重放、取得样衣并比较版本，再调用领域对象的可领用/借用/归还规则，通过 `CustodyCommandStore` 写入动作。应还日期校验使用注入时钟与业务时区，便于边界测试。

服务不信任客户端组织信息。来源快照中的应用服务说明职责，事务、条件写入及幂等落库由实际基础设施与调用链负责，验收须覆盖该链路。MySQL 保存业务事实，目录只读；对象存储不参与领借还的业务写事务。部署、数据迁移与兼容集中见公共设计，不逐功能复制。

### 验收场景及验证证据

关联 `openspec/specs/sales-sample-access/spec.md` 中 Requirement“销售仅执行本人领借还”，Scenario“领借及本人归还”“管理及跨人操作被拒绝”。交互恢复另外引用 Requirement“销售桌面与手机使用闭环”的 Scenario“完成操作与恢复”。同一功能可以关联多个 Requirement，机器索引在对应 Scenario 上声明其 requirement，保持业务叙述连续。

| 类别 | 准备与执行 | 预期结果 | 当前证据状态 |
|---|---|---|---|
| 正常 | 本人对符合条件的公共在库样衣提交有效版本及借期，再由本人归还 | 记录本人及归属，归还成功，列表/详情刷新 | 已有规格与实现；运行证据待项目盘点 |
| 异常 | 提交超过 7 天的借期或不允许领借的状态 | 拒绝且不写入流转 | 运行证据待项目盘点 |
| 并发 | 两个请求持相同旧版本竞争同一件样衣 | 过期版本拒绝，提示刷新，不覆盖新事实 | 需覆盖实际事务适配器 |
| 幂等 | 以同身份、样衣、动作及同键重复成功请求 | 返回重放结果，无重复业务写入 | 需记录数据库前后结果 |
| 权限 | 甲归还乙当前持有样衣，或普通员工直接调用管理接口 | 拒绝且业务事实不变 | 需记录服务端直接请求结果 |
| 恢复 | 模拟提交期间网络失败后用同键重试 | 能确认实际结果，无重复流转；失败保留输入 | 需真实环境或可控故障测试 |

验收记录必须包含执行者、环境、代码范围、步骤/命令、实际结果与原始日志。以上是可执行验收设计，未填写伪造 PASS；补齐后由项目具名审阅，再升级为已验证。已上线还需独立发布记录。
